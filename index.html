เซต (Sets) — นิยามและตัวอย่าง ออกสอบบ่อย

เซต (Set) คือ กลุ่มของวัตถุ (collection of distinct objects) ที่ไม่ซ้ำกัน
วัตถุแต่ละชิ้นในเซตเรียกว่า สมาชิก (element / member)
ถ้า \(b\) เป็นสมาชิกของเซต \(L\) เขียนว่า \(b \in L\)
เซตคืออะไรง่ายๆ? เซตก็เหมือน "ถุงของขวัญ" — ในถุงจะมีของอะไรบ้างก็ได้ แต่ต้องไม่มีของซ้ำกัน
คำสำคัญคือ "distinct" = ไม่ซ้ำ! ถ้าเขียน \(\{1, 2, 2, 3\}\) → จริงๆ แล้วเซตนี้คือ \(\{1, 2, 3\}\) เพราะเลข 2 ที่ซ้ำถือเป็นตัวเดียวกัน
และ ลำดับไม่สำคัญ — \(\{1, 2, 3\} = \{3, 1, 2\}\) เป็นเซตเดียวกัน
🎒 อุปมา: กระเป๋านักเรียน
คิดว่าเซตคือ "กระเป๋านักเรียน" — ในกระเป๋าจะมีดินสอ ยางลบ ไม้บรรทัด
• คุณไม่เอาดินสอ 2 แท่งเหมือนกันมาใส่ซ้ำ (distinct) ✅
• ดินสอจะอยู่บนสุดหรือล่างสุดก็ไม่ต่างกัน (order ไม่สำคัญ) ✅
• จะเปิดกระเป๋ามาถามว่า "มียางลบไหม?" = \(\text{ยางลบ} \in \text{กระเป๋า}\)

🎮 อุปมา: Inventory ในเกม RPG — ช่อง inventory เก็บ item ได้หลายอย่าง แต่ในเซตจะไม่ซ้อน stack — potion 1 ขวดก็คือ potion เท่านั้น

ตัวอย่างเซตที่สำคัญ

สัญลักษณ์ชื่อความหมาย
\(\mathbb{Z}\)Integers (จำนวนเต็ม)\(\{...,-2,-1,0,1,2,...\}\)
\(\mathbb{N}\)Natural Numbers (จำนวนธรรมชาติ)\(\{0, 1, 2, 3, ...\}\) (non-negative integers)
\(\mathbb{B}\)Truth Values (ค่าความจริง)\(\{T, F\}\)
\(\mathbb{R}\)Real Numbers (จำนวนจริง)จำนวนจริงทั้งหมด

วิธีแสดงเซต (2 วิธี)

1. การแจกแจงสมาชิก (Explicit Listing)

เขียนสมาชิกทั้งหมดในวงเล็บปีกกา: \(\mathbb{B} = \{T, F\}\)

2. การระบุคุณสมบัติ (Set-Builder Notation)

ระบุเงื่อนไขที่สมาชิกต้องเป็น:

\(\{x \mid x \in \mathbb{Z} \text{ and } x \bmod 2 = 0\}\) = เซตของจำนวนเต็มคู่

เขียนแบบย่อได้: \(\{x \in \mathbb{Z} \mid x \bmod 2 = 0\}\)

จากห้องเรียน: สัญลักษณ์ \(\mid\) อ่านว่า "such that" (ซึ่ง) — หมายความว่า "โดยที่" เป็นตัวคั่นระหว่างตัวแปรกับเงื่อนไข
ข้อสอบถามบ่อย: \(\emptyset \neq \{\emptyset\}\) — เซตว่างไม่เท่ากับเซตที่มีเซตว่างเป็นสมาชิก!
• \(\emptyset\) มี 0 สมาชิก
• \(\{\emptyset\}\) มี 1 สมาชิก (สมาชิกตัวนั้นคือ \(\emptyset\))

ความเท่ากันของเซต, เซตว่าง, เซตจำกัด/อนันต์

ความเท่ากันของเซต (Set Equality)

เซตสองเซต \(X\) และ \(Y\) เท่ากัน ก็ต่อเมื่อมีสมาชิกเหมือนกัน:
\(X = Y\) iff สำหรับทุก \(x \in X\) จะได้ \(x \in Y\), และสำหรับทุก \(x \in Y\) จะได้ \(x \in X\)

เซตว่าง (Empty Set) \(\emptyset\)

เซตที่ไม่มีสมาชิกเลย เขียนแทนด้วย \(\emptyset\) หรือ \(\{\}\)

เซตจำกัด vs อนันต์ (Finite vs Infinite)

  • เซตจำกัด (Finite): มีสมาชิกจำนวนจำกัด — เช่น \(\{1,2,3\}\) — สามารถหา bijection กับ \(\{1,2,...,n\}\) ได้
  • เซตอนันต์ (Infinite): มีสมาชิกจำนวนไม่จำกัด แบ่งเป็น:
    • Countably infinite (นับได้อนันต์): จับคู่ 1-1 กับ \(\mathbb{N}\) ได้ เช่น \(\mathbb{N}, \mathbb{Z}\)
    • Uncountably infinite (นับไม่ได้อนันต์): จับคู่ 1-1 กับ \(\mathbb{N}\) ไม่ได้ เช่น \([0,1], \mathbb{R}\)
จากห้องเรียน: "finite" = มีจำนวนแน่นอน (exact number), "infinite" = ไม่มีจำนวนแน่นอน (inexact number) — คิดง่ายๆ ว่า finite คือนับหมดได้ infinite คือนับไม่หมด

เซตย่อย (Subset) ออกสอบบ่อย

เซตย่อย (Subset): \(X \subseteq Y\) iff ทุก \(x \in X\) จะได้ \(x \in Y\)
— แปลไทย: X เป็นเซตย่อยของ Y ถ้าสมาชิกทุกตัวใน X อยู่ใน Y ด้วย
เซตย่อยแท้ (Proper Subset): \(X \subsetneq Y\) iff \(X \subseteq Y\) and \(X \neq Y\)
— แปลไทย: X เป็นส่วนหนึ่งของ Y แต่ไม่ใช่ Y ทั้งหมด

ตัวอย่าง

\(\mathbb{N} \subsetneq \mathbb{Z}\) — จำนวนธรรมชาติเป็น proper subset ของจำนวนเต็ม (เพราะ \(\mathbb{Z}\) มีจำนวนลบด้วย)

ข้อเท็จจริงพื้นฐาน (ใช้บ่อยมากในข้อสอบ)

  1. \(\emptyset \subseteq A\) สำหรับทุกเซต \(A\) — เซตว่างเป็นเซตย่อยของทุกเซต
  2. \(A \subseteq A\) สำหรับทุกเซต \(A\) — ทุกเซตเป็นเซตย่อยของตัวเอง
  3. ถ้า \(A \subseteq B\) และ \(B \subseteq A\) แล้ว \(A = B\) — ใช้พิสูจน์ความเท่ากันของเซต!
ข้อสอบถามบ่อย: "\(S \subseteq 2^S\) สำหรับทุกเซต \(S\)?" — คำตอบคือ False!
ตัวอย่าง: \(S = \{a\}\), \(2^S = \{\emptyset, \{a\}\}\). แต่ \(a \in S\) ไม่จำเป็นว่า \(a \in 2^S\) (เพราะ \(a\) ไม่ใช่เซต)
Proper Subset นับจำนวน: ถ้า \(A = \{a,b\}\) มีกี่ proper subset?
Subsets ทั้งหมด: \(\emptyset, \{a\}, \{b\}, \{a,b\}\) = 4 ชุด
Proper subsets (ไม่นับตัว \(A\) เอง): \(\emptyset, \{a\}, \{b\}\) = 3 ชุด
สูตร: จำนวน proper subsets = \(2^{|A|} - 1\)

การดำเนินการเซต ออกสอบบ่อย

Union (ยูเนียน — หรือ)

\(A \cup B = \{x \mid x \in A \lor x \in B\}\)
สมาชิกที่อยู่ใน A หรือ B (อย่างน้อยหนึ่งเซต)

Intersection (อินเตอร์เซกชัน — และ)

\(A \cap B = \{x \mid x \in A \land x \in B\}\)
สมาชิกที่อยู่ทั้งใน A และ B

Set Difference (ผลต่าง — แต่ไม่)

\(A \setminus B = \{x \mid x \in A \land x \notin B\}\)
สมาชิกที่อยู่ใน A แต่ไม่อยู่ใน B

Disjoint (ไม่มีสมาชิกร่วม)

เซต A, B เป็น disjoint ก็ต่อเมื่อ \(A \cap B = \emptyset\)

จากห้องเรียน:
• \(\cup\) = OR (มาจากตัว V = vel ภาษาละติน แปลว่า "หรือ")
• \(\cap\) = AND (พลิกกลับจาก ∪)
• \(A \setminus B\) = "A but not B"
ข้อสอบ: \(\{a, b, \{a,b\}\} - \{\{a\}\} = ?\)
คำตอบ: \(\{a, b, \{a,b\}\}\) (ไม่เปลี่ยน!) เพราะ \(\{a\}\) ไม่ใช่สมาชิกของเซตซ้าย — สมาชิกคือ \(a\), \(b\), \(\{a,b\}\) ไม่มี \(\{a\}\)

กฎของการดำเนินการเซต (ชุดที่ 1)

Idempotency (กฎเท่ากัน)

\(A \cup A = A\) และ \(A \cap A = A\)

— "idempotent" มาจากภาษาละติน: idem (เหมือน) + potens (กำลัง) = ทำซ้ำกี่ทีก็เหมือนเดิม

Commutativity (กฎสลับที่)

\(A \cup B = B \cup A\) และ \(A \cap B = B \cap A\)

— "commute" = เดินทาง/สลับ — สลับซ้ายขวาได้

Associativity (กฎเปลี่ยนกลุ่ม)

\((A \cup B) \cup C = A \cup (B \cup C)\)

\((A \cap B) \cap C = A \cap (B \cap C)\)

— "associate" = รวมกลุ่ม — จะจับกลุ่มคู่ไหนก่อนก็ได้ผลเหมือนกัน

เพราะ Associativity ทำให้เราเขียน General Union/Intersection ได้:

\(\bigcup\{A_1, A_2, A_3, ...\} = A_1 \cup A_2 \cup A_3 \cup ...\)

\(\bigcap\{A_1, A_2, A_3, ...\} = A_1 \cap A_2 \cap A_3 \cap ...\)

อาจารย์เน้น: กฎเหล่านี้หน้าตาคล้ายกับกฎของ + และ × ในเลขคณิต แต่มีข้อแตกต่างบางอย่าง (เช่น ∩ distribute over ∪ ก็ได้ ซึ่ง × distribute over + ได้ แต่ + ไม่ distribute over × ในเลขคณิต)

กฎของการดำเนินการเซต (ชุดที่ 2) ออกสอบบ่อย

Complement (ส่วนเติมเต็ม)

ถ้ามีเซตใหญ่ \(U\) ที่ทั้ง \(A, B \subseteq U\) ให้ \(\overline{A} = U \setminus A\)

  • \(A \setminus B = A \cap \overline{B}\)
  • \(\overline{A \cap B} = \overline{A} \cup \overline{B}\) (DeMorgan)
  • \(\overline{A \cup B} = \overline{A} \cap \overline{B}\) (DeMorgan)

Absorption Law (กฎดูดซับ)

\(A \cup (A \cap B) = A\) — ตัวเล็กถูกดูดซับโดยตัวใหญ่

\(A \cap (A \cup B) = A\)

Distributivity Law (กฎแจกแจง)

\(A \cup (B \cap C) = (A \cup B) \cap (A \cup C)\)

\(A \cap (B \cup C) = (A \cap B) \cup (A \cap C)\)

DeMorgan's Laws (กฎเดอมอร์แกน) ⭐

\(A \setminus (B \cup C) = (A \setminus B) \cap (A \setminus C)\) — "ลบ union = ตัดกัน ของลบแต่ละตัว"

\(A \setminus (B \cap C) = (A \setminus B) \cup (A \setminus C)\) — "ลบ intersection = รวมกัน ของลบแต่ละตัว"

เทคนิคจำ DeMorgan: "สลับเครื่องหมาย!" — เมื่อ complement/ลบเข้าไปในวงเล็บ ∪ กลายเป็น ∩ และ ∩ กลายเป็น ∪ เสมอ
ข้อสอบ: \(A - (B \cup C) = (A - B) \cap (A - C)\) — True ✓
แต่ \(A - (B \cup C) = (A - B) - C\) — ก็ True ✓ เช่นกัน! (Practice 2, Q1c)
ข้อสอบ: จงหาค่าของ \((\overline{A} \cup B) \cap (\overline{A} \cap (B \cup A))\)
1
พิจารณา \(\overline{A} \cap (B \cup A) = (\overline{A} \cap B) \cup (\overline{A} \cap A)\) (Distributivity)
2
\(\overline{A} \cap A = \emptyset\) ดังนั้น \(= (\overline{A} \cap B) \cup \emptyset = \overline{A} \cap B\)
3
ตอนนี้เหลือ \((\overline{A} \cup B) \cap (\overline{A} \cap B)\)
4
ใช้ Absorption: \((\overline{A} \cup B) \cap (\overline{A} \cap B) = \overline{A} \cap B\) ✓

คำตอบ: \(\overline{A} \cap B\)

การพิสูจน์กฎเซต ออกสอบเป็นข้อพิสูจน์

วิธีพิสูจน์ว่า A = B (สำหรับเซต)

พิสูจน์สองทาง: แสดงว่า \(A \subseteq B\) และ \(B \subseteq A\)
(จากห้องเรียน: ใช้ Venn's Diagram ช่วยวางแนวคิดก่อนเขียน proof)

ตัวอย่าง: พิสูจน์ \(A \cup (B \cap C) = (A \cup B) \cap (A \cup C)\)

ส่วนที่ 1: \(A \cup (B \cap C) \subseteq (A \cup B) \cap (A \cup C)\)

สมมติ \(x \in A \cup (B \cap C)\) มี 2 กรณี:
กรณี 1: \(x \in A\)
→ \(x \in A \cup B\) (เพราะ \(x \in A\)) และ \(x \in A \cup C\) (เพราะ \(x \in A\))
→ \(x \in (A \cup B) \cap (A \cup C)\) ✓

กรณี 2: \(x \in B \cap C\)
→ \(x \in B\) และ \(x \in C\)
→ \(x \in A \cup B\) (เพราะ \(x \in B\)) และ \(x \in A \cup C\) (เพราะ \(x \in C\))
→ \(x \in (A \cup B) \cap (A \cup C)\) ✓

ส่วนที่ 2: \((A \cup B) \cap (A \cup C) \subseteq A \cup (B \cap C)\)

สมมติ \(x \in (A \cup B) \cap (A \cup C)\)
→ \(x \in A \cup B\) และ \(x \in A \cup C\)
→ (\(x \in A\) or \(x \in B\)) and (\(x \in A\) or \(x \in C\))

กรณี 1: \(x \in A\) → \(x \in A \cup (B \cap C)\) ✓
กรณี 2: \(x \notin A\) → ต้อง \(x \in B\) และ \(x \in C\) → \(x \in B \cap C\) → \(x \in A \cup (B \cap C)\) ✓

ตัวอย่าง: พิสูจน์ \(A \cap B = A \setminus \overline{B}\) (ข้อสอบ Practice 4)

ทิศทาง ⊆: ถ้า \(x \in A \cap B\) → \(x \in A\) และ \(x \in B\) → \(x \notin \overline{B}\) → \(x \in A \setminus \overline{B}\) ✓

ทิศทาง ⊇: ถ้า \(x \in A \setminus \overline{B}\) → \(x \in A\) และ \(x \notin \overline{B}\) → \(x \in A\) และ \(x \in B\) → \(x \in A \cap B\) ✓

General Union, Power Set, Partition ออกสอบบ่อย

General Union \(\bigcup S\)

ถ้า \(S\) เป็นกลุ่มของเซต แล้ว \(\bigcup S\) = เซตที่ประกอบด้วยสมาชิกทั้งหมดจากทุกเซตใน \(S\)

\(S = \{\{a,b\}, \{c\}, \{a,d\}\}\) → \(\bigcup S = \{a,b,c,d\}\)
\(S = \{\{a,b\}, \{c\}, \{a,\{d,a\}\}\}\) → \(\bigcup S = \{a,b,c,\{d,a\}\}\)

สังเกต: \(\{d,a\}\) ยังคงเป็น "สมาชิกตัวหนึ่ง" ไม่ถูกแกะออก

ข้อสอบ: สำหรับทุกเซต \(L\), \(\bigcup 2^L = L\) — True ✓
เพราะ Power set ของ \(L\) มี subset ทุกตัว รวม \(\bigcup\) กลับมาก็ได้ \(L\) เดิม

Power Set (เซตกำลัง) \(2^S\)

\(2^S\) = เซตของทุก subset ของ \(S\) (รวม \(\emptyset\) และ \(S\) เอง)
คิดง่ายๆ: Power Set = "รายการทั้งหมดที่เป็นไปได้" ในการเลือกของจาก \(S\)
ถ้ามีของ \(n\) ชิ้น → แต่ละชิ้นคุณเลือก "เอา" หรือ "ไม่เอา" ก็ 2 ทางเลือก → รวม \(2 \times 2 \times ... \times 2 = 2^n\) วิธี → เลยได้ชื่อ \(2^S\)!
🍕 อุปมา: หน้าพิซซ่า
สมมติร้านมีหน้าให้เลือก 3 อย่าง: {🧀 ชีส, 🍄 เห็ด, 🌶️ พริก}
คุณจะสั่งพิซซ่าได้กี่แบบ? — ทุกแบบที่เป็นไปได้:
• ไม่ใส่อะไรเลย = \(\emptyset\) (พิซซ่าเปล่า)
• ใส่แค่ชีส = {🧀}
• ใส่ชีสกับเห็ด = {🧀, 🍄}
• ... รวมทั้งหมด \(2^3 = 8\) แบบ!
Power Set = เมนูพิซซ่าทุกหน้าที่เป็นไปได้

🎮 อุปมา: การเลือก character skill
มี skill 4 อย่าง เลือกจะติดตั้งแบบไหน = \(2^4 = 16\) build เป็นไปได้ (รวม "ไม่ติดตั้งอะไรเลย")
\(S = \{a\}\) → \(2^S = \{\emptyset, \{a\}\}\) (มี \(2^1 = 2\) สมาชิก)
\(S = \{a,b\}\) → \(2^S = \{\emptyset, \{a\}, \{b\}, \{a,b\}\}\) (มี \(2^2 = 4\) สมาชิก)
สูตร: \(|2^S| = 2^{|S|}\)
ตัวอย่างละเอียด: หา \(2^S\) เมื่อ \(S = \{a, b, c\}\)
ขั้น 1: นับ → \(|S| = 3\) → \(|2^S| = 2^3 = 8\) สมาชิก
ขั้น 2: ใช้ตารางเลข binary (000 → 111) แต่ละ bit แทน "เอา/ไม่เอา"
000 → \(\emptyset\)    001 → \(\{c\}\)    010 → \(\{b\}\)    011 → \(\{b,c\}\)
100 → \(\{a\}\)    101 → \(\{a,c\}\)    110 → \(\{a,b\}\)    111 → \(\{a,b,c\}\)
ผลลัพธ์: \(2^S = \{\emptyset, \{a\}, \{b\}, \{c\}, \{a,b\}, \{a,c\}, \{b,c\}, \{a,b,c\}\}\)
ผิดบ่อย: ลืมนับ \(\emptyset\) กับ \(S\) เอง! ทั้งสองเป็นสมาชิกของ \(2^S\) เสมอ
เช่น ถ้าถามว่า \(\{a,b\}\) มีกี่ subsets → ต้องตอบ 4 ไม่ใช่ 2
ถามตัวเอง: ถ้า \(S = \{1, 2, 3, 4\}\) → \(|2^S| = ?\)
\(2^4 = 16\) subsets — คิดง่ายๆ: 4 items แต่ละ item เลือก "เอา/ไม่เอา" = \(2 \times 2 \times 2 \times 2 = 16\)
ข้อสอบ: \(2^\emptyset = \emptyset\)? — False! \(2^\emptyset = \{\emptyset\}\) (มี 1 สมาชิกคือเซตว่าง)
ข้อสอบ: \(2^{A \cup B} = 2^A \cup 2^B\)? — False! เพราะ \(2^{A \cup B}\) มี \(A \cup B\) เป็นสมาชิก แต่ \(2^A \cup 2^B\) อาจไม่มี

Partition (พาร์ทิชัน)

พาร์ทิชันของเซต \(S\) คือเซต \(\Pi\) ของ subsets ของ \(S\) โดยที่:
1. แต่ละสมาชิกของ \(\Pi\) ไม่เป็นเซตว่าง
2. สมาชิกต่างตัวของ \(\Pi\) เป็น disjoint (ไม่มีสมาชิกร่วม)
3. \(\bigcup \Pi = S\) (รวมกันครบ \(S\))
\(S = \{a,b,c\}\)
✅ \(\Pi = \{\{a\}, \{b,c\}\}\) — partition ✓
❌ \(A = \{\{a\}, \{a,b\}, \{c\}\}\) — ไม่ใช่ เพราะ \(\{a\}\) กับ \(\{a,b\}\) ไม่ disjoint
❌ \(B = \{\{a\}, \{b,c\}, \emptyset\}\) — ไม่ใช่ เพราะมี \(\emptyset\)
ข้อสอบ: \(A = \{a,b,c\}\) มีกี่ partition?
\(\Pi_1 = \{\{a,b,c\}\}\)
\(\Pi_2 = \{\{a\}, \{b,c\}\}\)
\(\Pi_3 = \{\{b\}, \{a,c\}\}\)
\(\Pi_4 = \{\{c\}, \{a,b\}\}\)
\(\Pi_5 = \{\{a\}, \{b\}, \{c\}\}\)
คำตอบ: 5 partitions (Bell number \(B_3 = 5\))

คู่อันดับและผลคูณคาร์ทีเซียน

คู่อันดับ (Ordered Pair)

คู่อันดับ \((a,b)\) โดย \(a\) เป็น first component และ \(b\) เป็น second component
สำคัญ: \((a,b) \neq (b,a)\) ยกเว้นเมื่อ \(a = b\)

ผลคูณคาร์ทีเซียน (Cartesian Product)

\(A \times B \triangleq \{(a,b) \mid a \in A, b \in B\}\)
— เซตของทุกคู่อันดับ โดยตัวแรกมาจาก A ตัวที่สองมาจาก B
\(\{a,b\} \times \{a\} = \{(a,a), (b,a)\}\)
ระนาบ = \(\mathbb{R} \times \mathbb{R} = \mathbb{R}^2\)
ข้อสอบ: ถ้า \(A = \{0,1,2\}\), \(B = \emptyset\) แล้ว \(A \times B\) มีขนาดเท่าไร?
คำตอบ: \(|A \times B| = 0\) เพราะ \(A \times \emptyset = \emptyset\)

n-tuple และ n-fold Cartesian Product

\((a_1, a_2, ..., a_n)\) = ordered n-tuple

\(A_1 \times A_2 \times ... \times A_n\) = เซตของทุก ordered n-tuple

ฟังก์ชัน (Functions) ออกสอบบ่อย

ฟังก์ชัน (Function/Map): \(f: A \to B\) คือการกำหนดให้สมาชิกแต่ละตัวใน \(A\) มีค่าเดียว \(f(a)\) ใน \(B\)

• Domain (โดเมน): เซต \(A\) (ตัวตั้งต้น)
• Co-domain (โคโดเมน): เซต \(B\) (เซตเป้าหมาย)
• Image: \(f(a)\) = ค่าที่ \(a\) ถูกส่งไป
• Range: \(f(A) = \{f(a) \mid a \in A\}\) = เซตของ image ทั้งหมด

จำนวนฟังก์ชันจาก A ไป B (ข้อสอบ!)

เงื่อนไขจำนวนฟังก์ชันเหตุผล
\(A = \emptyset\)1มีฟังก์ชันว่าง \(\emptyset\) ตัวเดียว
\(B = \emptyset, A \neq \emptyset\)0ไม่มีที่ส่ง \(a\) ไป
\(|A|=1\)\(|B|\)เลือกส่งไปตัวไหนก็ได้ใน B
ทั่วไป\(|B|^{|A|}\)สมาชิกแต่ละตัวใน A มี |B| ตัวเลือก
ข้อสอบ Practice 4: \(A = \{0,1,2\}, B = \{1\}\) มีกี่ฟังก์ชัน?
คำตอบ: \(1^3 = 1\) — ฟังก์ชันเดียวคือ \(\{(0,1),(1,1),(2,1)\}\)

\(A = \{0,1,2\}, B = \emptyset\) มีกี่ฟังก์ชัน?
คำตอบ: 0 — เพราะต้องมีคู่ \((0,b)\) แต่ไม่มี \(b\) ใน \(B\)

ประเภทของฟังก์ชัน ออกสอบบ่อย

One-to-one (Injective — หนึ่งต่อหนึ่ง):
\(f: A \to B\) เป็น one-to-one iff สำหรับทุก \(a, a' \in A\) ที่ \(a \neq a'\) จะได้ \(f(a) \neq f(a')\)
— แปลง่ายๆ: ค่าต่างกันเข้า ต้องได้ผลต่างกันออก (ไม่มีชน)
Onto (Surjective — ทั่วถึง):
\(f: A \to B\) เป็น onto iff \(B = f(A)\)
— แปลง่ายๆ: สมาชิกทุกตัวใน B ถูกส่งถึง (ไม่มีตัวตกหล่น)
Bijection (ฟังก์ชันหนึ่งต่อหนึ่งทั่วถึง):
\(f\) เป็น bijection iff \(f\) เป็น one-to-one และ onto
— จับคู่สมบูรณ์ทุกตัว
เซต \(A\) และ \(B\) มีจำนวนสมาชิกเท่ากัน (equinumerous) ก็ต่อเมื่อมี bijection ระหว่าง \(A\) กับ \(B\)
ข้อสอบ Practice 1: \(f: \mathbb{N} \to \Sigma^*\) โดย \(\Sigma = \{0,...,9\}\) แปลงจำนวนเป็น decimal representation
• \(f\) เป็น one-to-one? ✅ (จำนวนต่างกัน → representation ต่างกัน)
• \(f\) เป็น onto \(\Sigma^*\)? ❌ (ไม่มี \(n\) ที่ \(f(n) = 001\))
• \(f\) เป็น bijection? ❌ (เพราะไม่ onto)
• \(\mathbb{N}\) กับ \(\Sigma^*\) equinumerous? ✅ (ใช้ bijection ตัวอื่นได้)

Function Composition & Relations ออกสอบบ่อย

การประกอบฟังก์ชัน (Function Composition)

ให้ \(f: A \to B\) และ \(g: B \to C\) การประกอบ \(f \cdot g: A \to C\) กำหนดโดย:
\(f \cdot g(a) = g(f(a))\)
— ทำ f ก่อน แล้วเอาผลลัพธ์ไปทำ g
\(f: \mathbb{N} \times \mathbb{N} \to \mathbb{N}\) โดย \(f(m,n) = m+n\)
\(g: \mathbb{N} \to \mathbb{N}\) โดย \(g(k) = 2k\)
\(f \cdot g(m,n) = g(f(m,n)) = g(m+n) = 2(m+n)\)

ความสัมพันธ์ (Binary Relation)

Binary relation บนเซต \(A, B\) คือ subset ของ \(A \times B\)
เช่น \(R = \{(m,n) \mid m \geq n\} \subseteq \mathbb{Z} \times \mathbb{Z}\)

Relation Inverse \(R^{-1}\)

\((b,a) \in R^{-1}\) iff \((a,b) \in R\) — กลับข้าง!

Relation Composition \(Q \cdot R\)

\(Q \cdot R = \{(a,c) \mid \exists b \text{ s.t. } (a,b) \in Q \text{ and } (b,c) \in R\}\)

ข้อสอบ Practice 2: \(R = \{(a,b),(b,c),(c,f),(b,a)\}\)
\(R^{-1}\): กลับทุกคู่ → \(\{(b,a),(c,b),(f,c),(a,b)\}\) — มี 4 สมาชิก

\(R \circ R\): หาทุก \((a,c)\) ที่มี \(b\) เป็นตัวกลาง:
• \((a,b)\) + \((b,c)\) → \((a,c)\) ✓
• \((a,b)\) + \((b,a)\) → \((a,a)\) ✓
• \((b,c)\) + \((c,f)\) → \((b,f)\) ✓
• \((b,a)\) + \((a,b)\) → \((b,b)\) ✓
• \((b,c)\) + → ไม่มี \((c,?)\) นอกจาก \((c,f)\) → \((b,f)\) (ซ้ำ)
• \((b,a)\) + \((a,b)\) → \((b,b)\) (ซ้ำ), \(+ (b,c)\) ไม่ใช่ตัวกลาง
ผลลัพธ์: \(\{(a,c),(a,a),(b,f),(b,b),(b,c)\}\) — มี 5 สมาชิก

\(|2^R| = 2^4 = 16\)

Functions vs Relations

เทคนิคจากห้องเรียน — วิธีตรวจว่า Relation เป็นฟังก์ชัน:
"ต้องมี outgoing link เดียวสำหรับแต่ละ node ทาง LHS"
— ถ้ามีสมาชิก \((a,b)\) และ \((a,c)\) โดย \(b \neq c\) → ไม่เป็นฟังก์ชัน (one-to-many)

คุณสมบัติของ Relations ออกสอบทุกชุด

ให้ \(R \subseteq A \times A\) เป็น binary relation บนเซต \(A\):

Reflexive (สะท้อน): สำหรับทุก \(a \in A\), \((a,a) \in R\)
→ "ทุกตัวชี้ไปหาตัวเอง" (self-loop ทุกตัว)

Symmetric (สมมาตร): ถ้า \((a,b) \in R\) แล้ว \((b,a) \in R\)
→ "ไปก็ได้ กลับก็ได้" (back & forth)

Transitive (ถ่ายทอด): ถ้า \((a,b) \in R\) และ \((b,c) \in R\) แล้ว \((a,c) \in R\)
→ "ต่อกันได้" (ผ่านตัวกลาง = ตรงไปเลย)

Antisymmetric (ปฏิสมมาตร): ถ้า \((a,b) \in R\) และ \(a \neq b\) แล้ว \((b,a) \notin R\)
→ "ทางเดียว ห้ามกลับ" (no return)
ตัวอย่างจากชีวิตจริง (จากห้องเรียน):
• Reflexive: "รักตัวเอง" (self-love) — ทุกคนรักตัวเอง
• Symmetric: "แต่งงาน" — ถ้า A แต่งกับ B ก็ B แต่งกับ A
• Transitive: "บรรพบุรุษ" (ancestor) — ถ้า A เป็นบรรพบุรุษ B, B เป็นบรรพบุรุษ C → A เป็นบรรพบุรุษ C
• Equivalence: "สัญชาติเดียวกัน" (same nationality) — reflexive + symmetric + transitive

Equivalence Relation (ความสัมพันธ์สมมูล)

\(R\) เป็น equivalence relation iff \(R\) เป็น reflexive + symmetric + transitive

Partial Order (อันดับบางส่วน)

\(R\) เป็น partial order iff \(R\) เป็น reflexive + transitive + antisymmetric
ข้อสอบสุดฮิต: ให้ \(R = \emptyset\) เป็น relation บน \(A\) แล้ว \(R\) เป็น?
• Reflexive? ❌ (ไม่มี \((a,a)\) เลย... ยกเว้น \(A = \emptyset\))
• Symmetric? ✅ (เป็น vacuously true — ไม่มี \((a,b)\) ให้ตรวจ)
• Antisymmetric? ✅ (vacuously true เช่นกัน)
• Transitive? ✅ (vacuously true)
• Partial order? ❌ (เพราะไม่ reflexive)
ข้อสอบ Practice 3: "mother" relation บนเซตครอบครัว
• Symmetric? ❌ (ถ้า A เป็นแม่ B ไม่ได้แปลว่า B เป็นแม่ A)
• Antisymmetric? ✅ (ถ้า A เป็นแม่ B แล้ว B ไม่ใช่แม่ A)

"ancestor" relation:
• Transitive? ✅
• Partial order? ❌ (ไม่ reflexive — คนไม่ใช่บรรพบุรุษตัวเอง)

Equivalence Class และ A modulo R

Equivalence Class (ชั้นสมมูล)

ให้ \(R\) เป็น equivalence relation บน \(A\) สำหรับแต่ละ \(a \in A\):
\([a]_R = \{b \mid (a,b) \in R\}\)
— "กลุ่มของทุกสมาชิกที่สัมพันธ์กับ a"
จากห้องเรียน: ถ้า R = "สัญชาติเดียวกัน" แล้ว \([\text{ประชา}]_R\) = คนไทยทุกคนในเซต

คุณสมบัติสำคัญ

สำหรับทุก \(a, b \in A\): ถ้า \([a]_R = [b]_R\) (อยู่กลุ่มเดียวกัน) หรือ \([a]_R\) กับ \([b]_R\) เป็น disjoint (ไม่มีสมาชิกร่วม)

A modulo R

\(A/R = \{[a]_R \mid a \in A\}\)
\(A/R\) เป็น partition ของ \(A\) — ไม่มีช่องว่าง ไม่ซ้อนทับ
ให้ \(\mathbb{Z}^+\) = positive integers, กำหนด \((p,q) \equiv (r,s)\) iff \(ps = qr\)
นี่คือ equivalence relation ที่กำหนดจำนวนตรรกยะ!
เช่น \((2,3) \equiv (4,6)\) เพราะ \(2 \times 6 = 3 \times 4\) → ทั้งคู่แทน \(\frac{2}{3}\)
\((\mathbb{Z}^+ \times \mathbb{Z}^+) / \equiv\) = เซตของจำนวนตรรกยะ \(\mathbb{Q}^+\)

อันดับ (Orders), เส้นทาง (Path), วงรอบ (Cycle)

Partial Order (อันดับบางส่วน)

\(R\) เป็น partial order iff reflexive + transitive + antisymmetric

ตัวอย่าง: \(\subseteq\) บน power set เป็น partial order

Total Order (อันดับเต็ม)

Partial order \(R \subseteq A \times A\) เป็น total order iff สำหรับทุก \(a, b \in A\):
\((a,b) \in R\) หรือ \((b,a) \in R\)
— ทุกคู่เปรียบเทียบกันได้ เช่น ≤ บน \(\mathbb{Z}\)

เส้นทาง (Path) และ วงรอบ (Cycle)

Path จาก \(a\) ไป \(b\) ใน \(R\) = ลำดับ \(a_1, ..., a_n\) โดย \(a = a_1\), \(b = a_n\) และ \((a_i, a_{i+1}) \in R\)

Cycle = path ที่ \(a_1 = a_n\) และทุกจุดบนเส้นทาง distinct (ไม่ซ้ำ)

จากห้องเรียน: "traverse from a to b via R" = เดินจาก a ไป b ผ่าน R ทีละ step — "One way or another"

การนับ — เซตจำกัดและอนันต์ ออกสอบบ่อย

Equinumerous (มีจำนวนเท่ากัน): \(A\) กับ \(B\) equinumerous iff มี bijection \(f: A \to B\)

Cardinality (จำนวนเชิงการนับ): \(|A| = n\) iff \(A\) equinumerous กับ \(\{1,...,n\}\)

Countably infinite: equinumerous กับ \(\mathbb{N}\)
Uncountably infinite: infinite แต่ไม่ equinumerous กับ \(\mathbb{N}\)
Countable = "สามารถ list ทีละตัวได้ครบ (ในเวลาไม่จำกัด)"
คิดว่าคุณกำลังเรียกชื่อทีละคนใน list — ถ้าเรียกไปเรื่อยๆตัวสุดท้ายทุกตัวจะได้รับการเรียกในสักตอนหนึ่ง → countable
Uncountable = "list ต่อให้เรียกไม่ครบชาติเลย" — มีตัวที่ไม่มีทางถึงในลำดับใดก็ตาม (จำนวนจริง \(\mathbb{R}\) เป็นตัวอย่าง)
🏨 อุปมา: โรงแรม Infinite Hilbert Hotel
โรงแรมมีห้อง \(\infty\) ห้อง หมายเลข 1, 2, 3, ... ทุกห้องเต็ม!
• แขกใหม่ 1 คนมา: ทุกคนย้ายจากห้อง n → ห้อง n+1 → ห้อง 1 ว่าง! (\(\mathbb{N}\) ยัง countable)
• รถบัส \(\infty\) คนมา: ทุกคนย้ายจาก n → 2n → ห้องเลขคี่ว่างหมด → รับได้! (union countable)
• รถบัส \(\infty\) คัน คันละ \(\infty\) คนมา: ใช้ dovetailing! → ยังรับได้! (\(\mathbb{N} \times \mathbb{N}\) countable)
• แต่ถ้าเป็น รถบัสของจำนวนจริง \(\mathbb{R}\) → รับไม่ได้! (uncountable)

🎮 อุปมา: การเข้าคิวใน MMO
Countable = คิวที่มีเลขต่อคน (server เรียกทีละคนได้ครบ) — Uncountable = คิวที่ไม่มีเลข ต่อให้เรียกไปนานแค่ไหนก็ยังมีคนเหลือ
ตัวอย่าง: พิสูจน์ว่า "จำนวนคี่บวก" เป็น countably infinite
ขั้น 1: ตั้ง \(A = \{1, 3, 5, 7, ...\}\)
ขั้น 2: หา bijection \(f: \mathbb{N} \to A\) — สูตร \(f(n) = 2n + 1\)
ขั้น 3: ตรวจ — \(f(0) = 1, f(1) = 3, f(2) = 5, ...\) → 1-1 และ onto ✓
สรุป: A equinumerous กับ \(\mathbb{N}\) → countably infinite ✓

ข้อเท็จจริงสำคัญ (ข้อสอบ!)

  • ทุก subset ของ finite set เป็น finite ✓
  • ทุก subset ของ countably infinite set เป็น finite หรือ countably infinite ✓ Practice 4
  • \(\mathbb{N} \times \mathbb{N}\) เป็น countably infinite ✓ (ใช้ dovetailing)
  • Union ของ countably infinite collection ของ countably infinite sets เป็น countably infinite ✓
Dovetailing (จากห้องเรียน): วิธีนับ \(\mathbb{N} \times \mathbb{N}\) — map \((i,j)\) ไปที่ตำแหน่ง \(1000i + j\) (เช่น Python: for i in range(1000): for j in range(1000): print((i,j), 1000*i+j))
ข้อสอบ Practice 4: ข้อใดถูกต้อง?
(a) ทุก subset ของ countably infinite set เป็น finite → ❌
(b) ทุก subset ของ countably infinite set เป็น finite หรือ countably infinite → ✅
(c) ทุก subset ของ uncountably infinite set เป็น finite → ❌
(d) ทุก subset ของ uncountably infinite set เป็น finite หรือ countably infinite → ❌

เทคนิคพิสูจน์ 1: อุปนัยเชิงคณิตศาสตร์ (Mathematical Induction)

หลักอุปนัยเชิงคณิตศาสตร์: ให้ \(A\) เป็นเซตของจำนวนธรรมชาติ ถ้า:
1. \(0 \in A\) (Base case)
2. สำหรับทุก \(n\): ถ้า \(\{0,1,...,n\} \subseteq A\) แล้ว \(n+1 \in A\) (Inductive case)
แล้ว \(A = \mathbb{N}\) (เป็นจริงสำหรับทุกจำนวนธรรมชาติ)
จากห้องเรียน: "inducere" (ละติน) = นำไปสู่
Base case = เริ่มต้นจุดแรก
Inductive case = ถ้ารู้ว่าจริงถึง n แล้วพิสูจน์ว่า n+1 ก็จริง
พิสูจน์: \(1 + 2 + ... + n = \frac{n(n+1)}{2}\)
1
Base case (n=0): ผลรวมเป็น 0 = \(\frac{0 \cdot 1}{2} = 0\) ✓
2
Inductive hypothesis: สมมติว่า \(1+2+...+n = \frac{n(n+1)}{2}\)
3
Inductive step (n+1):
\(1+2+...+n+(n+1) = \frac{n(n+1)}{2} + (n+1) = \frac{n(n+1) + 2(n+1)}{2} = \frac{(n+1)(n+2)}{2}\) ✓

เทคนิคพิสูจน์ 2: หลักรังนกพิราบ (Pigeonhole Principle)

ถ้า \(A, B\) เป็นเซตจำกัดและ \(|A| > |B|\) แล้ว ไม่มี one-to-one function จาก \(A\) ไป \(B\)

— ถ้ามีนกพิราบ 10 ตัวแต่รังมี 9 รัง ต้องมีอย่างน้อย 1 รังที่มีนก ≥ 2 ตัว

ตัวอย่าง: มีนักเรียน 79 คน เก้าอี้ 70 ตัว จะให้นั่งคนละตัวได้ไหม?
ไม่ได้! เพราะ \(|A| = 79 > 70 = |B|\) → ไม่มี one-to-one function จาก นักเรียน → เก้าอี้
เทคนิคพิสูจน์ Pigeonhole ด้วย Induction (จากห้องเรียน):
1. FACT: ถ้า \(|B| = 0\) แล้วไม่มี 1-to-1 function
2. สมมติมี 1-to-1 function \(f\) ที่ map สมาชิก \(e\) ไปยัง \(f(e)\)
3. ลบ \(e\) ออกจาก \(A\) และลบ \(f(e)\) ออกจาก \(B\)
4. แสดงว่าจะเหลือ \(|B| = 0\) ในที่สุด → ขัดแย้ง

เทคนิคพิสูจน์ 3: หลักทแยงมุม (Diagonalization) ออกสอบบ่อย

ให้ \(R\) เป็น binary relation บนเซต \(A\) กำหนด:
• Diagonal set: \(D = \{a \in A \mid (a,a) \notin R\}\) — "สมาชิกที่ไม่ชี้ไปหาตัวเอง"
• Row set: \(R_a = \{b \in A \mid (a,b) \in R\}\) — "สมาชิกที่ a ชี้ไป"

แล้วสำหรับทุก \(a \in A\): \(R_a \neq D\) — Diagonal set ไม่เท่ากับ row set ใดๆ ทั้งสิ้น!
ทำไมเรียก "ทแยงมุม"? ถ้าเขียน relation \(R\) เป็นตาราง (แถว = a, คอลัมน์ = b) ตำแหน่ง \((a,a)\) จะอยู่บนเส้นทแยงพอดี!
เทคนิคนี้คือ "สร้างเซตพิเศษที่ตรงข้ามกับทุกแถว โดยดูจากตำแหน่งทแยง" → รับรองว่ามันไม่เหมือนแถวไหนเลย
🎓 อุปมา: เกม "ตอบไม่เหมือนใคร"
สมมติในห้องเรียน 5 คน ครูให้ทุกคนเขียนรายการอาหารโปรด
• คนที่ 1 เขียน: 🍕🍔🍜
• คนที่ 2 เขียน: 🍕🍟
• คนที่ 3 เขียน: 🍜
คุณอยากเขียนรายการที่ ไม่ตรงกับใครเลย ทำยังไง?
👉 สร้าง diagonal: ดูตำแหน่งทแยง — คนที่ i ชอบอาหารตัวที่ i ไหม? ถ้าชอบ → ฉันไม่ใส่ ถ้าไม่ชอบ → ฉันใส่
ผลลัพธ์: รายการของคุณต่างจากทุกคนอย่างน้อย 1 ตำแหน่ง (ตำแหน่งทแยง)!

🎮 อุปมา: เจ้าของหมีเทดดี้
Barber's paradox ในเวอร์ชันคณิตศาสตร์ — "ฉันคือคนที่ตัดผมให้คนที่ไม่ตัดผมให้ตัวเอง" แล้วใครตัดให้ฉัน?
ตัวอย่างละเอียด: \(A = \{1,2,3,4,5\}\), \(R = \{(1,3),(2,4),(3,5),(5,1),(2,3),(1,1),(4,2),(4,4)\}\)
ขั้น 1: เขียนตาราง (แถว a, คอลัมน์ b) — ใส่ 1 ถ้า \((a,b) \in R\)
แถว 1: (1,1)=1, (1,3)=1 → \(R_1 = \{1,3\}\)
แถว 2: (2,3)=1, (2,4)=1 → \(R_2 = \{3,4\}\)
แถว 3: (3,5)=1 → \(R_3 = \{5\}\)
แถว 4: (4,2)=1, (4,4)=1 → \(R_4 = \{2,4\}\)
แถว 5: (5,1)=1 → \(R_5 = \{1\}\)
ขั้น 2: หา diagonal \(D\) — ดูตำแหน่ง \((a,a)\): \((1,1) \in R\) ✗, \((2,2) \notin R\) ✓, \((3,3) \notin R\) ✓, \((4,4) \in R\) ✗, \((5,5) \notin R\) ✓
\(D = \{2, 3, 5\}\) ← เลขที่ (a,a) ไม่อยู่ใน R
ขั้น 3: ยืนยัน — \(D \neq R_1, R_2, R_3, R_4, R_5\) ทุกตัว ✓
ผิดบ่อย: สับสนระหว่าง \(D\) กับ \(D'\)!
• \(D = \{a \mid (a,a) \notin R\}\) — ใช้ได้เสมอ ทำ diagonal principle ได้
• \(D' = \{a \mid (a,a) \in R\}\) — ใช้ไม่ได้! อาจเท่ากับ row set บางแถว
ข้อสอบ Practice 4: \(A = \{a,b,c,d\}\), \(R = \{(a,a),(b,b),(c,c),(d,d)\}\)
Row set ของ a: \(R_a = \{x \mid (a,x) \in R\} = \{a\}\) (singleton)
Diagonal set: \(D = \{x \mid (x,x) \notin R\} = \emptyset\) (ทุกตัวมี self-loop)
ตรวจ: \(R_a = \{a\} \neq \emptyset = D\) ✓ — Diagonal principle ถูกต้อง!

\(2^{\mathbb{N}}\) เป็น uncountably infinite

พิสูจน์โดยใช้ Diagonalization:
สมมติ (proof by contradiction) ว่า \(2^{\mathbb{N}}\) เป็น countably infinite
→ มี bijection \(f: \mathbb{N} \to 2^{\mathbb{N}}\)
กำหนด \(R = \{(n,m) \mid m \in f(n)\}\)
Diagonal set \(D = \{n \mid n \notin f(n)\}\) ← \(D\) เป็น subset ของ \(\mathbb{N}\) → \(D \in 2^{\mathbb{N}}\)
เพราะ \(f\) เป็น bijection → มี \(k\) ที่ \(f(k) = D\)
แต่ \(k \in D \iff k \notin f(k) = D\) ← ขัดแย้ง! ∎

ตัวอักษร (Alphabet), สตริง (String), ภาษา (Language) ออกสอบบ่อย

Alphabet (\(\Sigma\)): เซตจำกัดของสัญลักษณ์ เช่น \(\Sigma = \{0,1\}\) หรือ \(\Sigma = \{a,b\}\)

String: ลำดับจำกัดของสัญลักษณ์จาก \(\Sigma\) เช่น \(aab, 0110\)

Empty string: \(e\) (หรือ \(\varepsilon\)) — สตริงที่ไม่มีสัญลักษณ์เลย, \(|e| = 0\)

Concatenation: \(x \cdot y\) หรือ \(xy\) = สตริง \(x\) ตามด้วย \(y\) (associative: \((xy)z = x(yz)\))

String Operations

  • Length: \(|hello| = 5\)
  • Substring: \(v\) เป็น substring ของ \(w\) ถ้า \(w = xvy\) สำหรับบาง \(x, y\)
  • Power: \(\omega^0 = e\), \(\omega^{n+1} = \omega^n \cdot \omega\) (ทำซ้ำ \(n\) รอบ)
  • Reversal: \(e^R = e\), \((ua)^R = a \cdot u^R\)
จากห้องเรียน: x = prefix, y = suffix, v = infix (substring)
"fixere" (ละติน) = stay — pre = before, sub/suf = after

\(\Sigma^*\) และ ภาษา (Language)

\(\Sigma^*\) = เซตของทุกสตริงที่สร้างจาก \(\Sigma\) (รวม \(e\))
ตัวอย่าง: \(\{a,b\}^* = \{e, a, b, aa, ab, ba, bb, aaa, ...\}\)

ภาษา (Language): เซต \(L\) ใดๆ ของสตริงเหนือ \(\Sigma\) คือ \(L \subseteq \Sigma^*\)
ข้อสอบ: \(\Sigma^*\) countably infinite? → ✅
\(2^{\Sigma^*}\) countably infinite? → ❌ (uncountably infinite! — ใช้ diagonalization)

Language Operations

  • Complement: \(\overline{A} = \Sigma^* \setminus A\)
  • Concatenation: \(L_1 \cdot L_2 = \{xy \mid x \in L_1, y \in L_2\}\)
  • Kleene Star: \(L^* = L^0 \cup L^1 \cup L^2 \cup ... = \bigcup_{n \geq 0} L^n\) โดย \(L^0 = \{e\}\)
  • Kleene Plus: \(L^+ = L^1 \cup L^2 \cup ... = \bigcup_{n \geq 1} L^n\)
ข้อสอบสุดฮิต: \(L^+ = L^* \setminus \{e\}\) เสมอ? → ไม่เสมอ!
Counter-example: ถ้า \(L = \{e\}\) แล้ว \(L^+ = \{e\}\) แต่ \(L^* \setminus \{e\} = \emptyset\)

\(L^* = LL^*\) เสมอ? → ไม่! เพราะ \(e \in L^*\) แต่ \(e\) อาจไม่อยู่ใน \(LL^*\) (ถ้า \(e \notin L\))

\(L^* = LL^+\) เสมอ? → ไม่! เหมือนกัน \(L^* = LL^+\) iff \(e \in L\)

\(L^* = (L^*)^*\) เสมอ? → ใช่! ✅

ภาษาปรกติ (Regular Languages) & นิพจน์ปรกติ (Regular Expressions) ออกสอบทุกชุด

Regular Languages — นิยาม

เซตของภาษาปรกติ (regular languages) คือเซตที่เล็กที่สุดที่สอดคล้องเงื่อนไข:
1. \(\emptyset\) เป็น regular
2. สำหรับทุก \(a \in \Sigma\), \(\{a\}\) เป็น regular
3. ถ้า \(A, B\) เป็น regular แล้ว \(A^*\), \(A \cup B\), \(A \cdot B\) ก็เป็น regular

Regular Expressions — นิพจน์ปรกติ

Regular expression เหนือ \(\Sigma\) สร้างจาก:
• \(\emptyset\) เป็น regular expression, \(L(\emptyset) = \emptyset\)
• ทุก \(a \in \Sigma\) เป็น regular expression, \(L(a) = \{a\}\)
• ถ้า \(\alpha, \beta\) เป็น RE แล้ว \((\alpha \cdot \beta)\), \(\alpha^*\), \(\alpha \cup \beta\) ก็เป็น RE
โดย \(L(\alpha \cdot \beta) = L(\alpha) \cdot L(\beta)\), \(L(\alpha^*) = L(\alpha)^*\), \(L(\alpha \cup \beta) = L(\alpha) \cup L(\beta)\)
Regex = สูตรอธิบาย pattern
คิดว่า regex เป็น "สูตรทำอาหาร" — บอกวิธีสร้างสตริงที่ยอมรับได้
• \(a\) = "ต้องมีตัว a"
• \(a \cup b\) = "เอา a หรือ b ก็ได้" (choice)
• \(ab\) = "a ก่อน แล้วตามด้วย b" (sequence)
• \(a^*\) = "a กี่ตัวก็ได้ รวมถึง 0 ตัว" (repeat, รวมว่างเปล่าได้)
🎮 อุปมา: Cheat code ในเกม
Regex เป็นเหมือน pattern ของ cheat code:
• \(a^*bc\) = "กด a กี่ครั้งก็ได้ แล้วกด b, c" → \(bc, abc, aabc, aaabc, ...\) ผ่านหมด
• \((a \cup b)c\) = "กด a หรือ b ก่อน แล้วกด c" → \(ac\) หรือ \(bc\)

ตัวอย่างเยอะๆ: แปล regex → ภาษา

จริงๆ แล้วภาษานี้คือ "a หลายตัวตามด้วย b หลายตัว จำนวนไม่ต้องเท่ากัน" เช่น \(aab, aaabb\) ก็ยอมรับ

DFA — Deterministic Finite Automaton ออกสอบทุกชุด

ปัญหาการรับรอง (Acceptance Problem)

กำหนดภาษา regular \(L\) และสตริง \(\omega\) → ตรวจว่า \(\omega \in L\) หรือไม่?

DFA คือ 5-tuple \(M = (K, \Sigma, \delta, s, F)\) โดย:
• \(K\) = เซตจำกัดของ states (สถานะ)
• \(\Sigma\) = alphabet (ตัวอักษร input)
• \(s \in K\) = initial state (สถานะเริ่มต้น)
• \(F \subseteq K\) = final states (สถานะยอมรับ)
• \(\delta: K \times \Sigma \to K\) = transition function (ฟังก์ชันเปลี่ยนสถานะ)
DFA = "หุ่นยนต์อ่านตัวอักษร"
คิดว่ามีหุ่นยนต์ตัวหนึ่ง เดินไปตามลูกศรบนแผนที่ทีละก้าว โดยดูจากตัวอักษรที่อ่านได้:
• เริ่มยืนที่ \(s\) (initial state)
• อ่านตัวอักษรทีละตัวจาก input
• ตัวอักษรบอก "ไปทางไหน" — เดินตามลูกศรทันที
• อ่านครบ → ยืนอยู่ในวงกลมคู่ (\(F\)) ไหม? ถ้าใช่ = ยอมรับ ถ้าไม่ใช่ = ปฏิเสธ
"Deterministic" = แต่ละท่าไม่มีเสี่ยงดวง! อยู่ที่ state ไหน อ่าน symbol อะไร → ไปที่ไหน มีคำตอบเดียวเท่านั้น
🚦 อุปมา: ไฟจราจร (State Machine ตัวจริง!)
ไฟจราจรมี 3 state: 🟢 เขียว, 🟡 เหลือง, 🔴 แดง
Input = "หมดเวลา 30 วิ" — transition ตายตัว:
เขียว → หมดเวลา → เหลือง → หมดเวลา → แดง → หมดเวลา → เขียว (loop)
ไม่มีการ "เดา" — deterministic 100%!

DFA — การคำนวณ (Computation) ออกสอบทุกชุด

Configuration (การกำหนดค่า): คู่ \((q, \omega)\) โดย \(q \in K\) (state ปัจจุบัน) และ \(\omega \in \Sigma^*\) (input ที่เหลือ)
Yields in one step (\(\vdash_M\)):
\((q, \omega) \vdash_M (q', \omega')\) iff มี \(\sigma \in \Sigma\) ที่ \(\omega = \sigma\omega'\) และ \(q' = \delta(q, \sigma)\)
— อ่านตัวอักษรหน้าสุด แล้วเปลี่ยน state ตาม \(\delta\)
\(\vdash_M^*\) = reflexive transitive closure ของ \(\vdash_M\) (ศูนย์หรือหลาย steps)
Acceptance: สตริง \(\omega\) accepted โดย \(M\) iff มี \(q \in F\) ที่ \((s, \omega) \vdash_M^* (q, e)\)
\(L(M) = \{\omega \mid M \text{ accepts } \omega\}\) = ภาษาที่ \(M\) รับรอง

\(\vdash (q, aba)\) — อ่าน a, \(\delta(q,a)=s\)

\(\vdash (s, ba)\) — อ่าน b, \(\delta(s,b)=q\)
6
\(\vdash (q, a)\) — อ่าน a, \(\delta(q,a)=s\)
7
\(\vdash (s, e)\) — input หมด, state \(s \in F\) → ACCEPTED ✅
ข้อสอบ Practice 4: ระวังเขียน \(F\) ต้องเป็นเซต ไม่ใช่ element!
\(F = q_0\) ❌ → \(F = \{q_0\}\) ✅

NFA — Nondeterministic Finite Automaton ออกสอบบ่อย

NFA คือ 5-tuple \(M = (K, \Sigma, \Delta, s, F)\) โดย:
• \(K, \Sigma, s, F\) — เหมือน DFA
• \(\Delta \subseteq K \times (\Sigma \cup \{e\}) \times K\) = transition relation (ไม่ใช่ function!)
— แต่ละ state + input อาจมีหลายทางเลือก หรือไม่มีเลย
NFA = "หุ่นยนต์ที่โคลนตัวเองได้"
ต่างจาก DFA (ไปทางเดียว) — NFA สามารถ:
1. 🌟 "เดา" หลายทางพร้อมกัน — เจอทางแยกก็ไปทุกทางในเวลาเดียว (parallel universes!)
2. 🌟 ε-transition — เปลี่ยน state โดยไม่อ่าน input (เดินฟรี)
3. 🌟 ทางไปได้ 0 ทาง ก็ได้ (dead-end → สาย universe นั้นตาย)

ยอมรับ: ถ้ามีอย่างน้อย 1 universe ไปถึง final state → accepted!
🎮 อุปมา: RPG กับ Save Point
คิดว่าคุณเล่น RPG ที่:
• เจอทางแยก → คุณ "save" แล้วลองไปทุกทาง (โคลนตัวเอง)
• ถ้าทางไหนตัน → ปิดสาย นั้นซะ
• ถ้าทางไหนชนะ boss (ไปถึง final state) → คุณชนะเกม!

🚪 อุปมา: Door of Destiny
ประตูหลายบานจากห้องเดียว — DFA บอกให้เข้าบานที่กำหนดตายตัว, NFA เข้าทุกบานพร้อมกัน

🕸️ อุปมา: Doctor Strange & Multiverse
NFA คือ "สำรวจ multiverse" — ทุกความเป็นไปได้ดำเนินคู่ขนาน

👻 ε-transition = "teleport ฟรี"
เดินทะลุกำแพงโดยไม่ต้องใช้พลัง (input) — ไม่กิน turn
ตัวอย่าง: NFA รับ \((ab \cup aba)\)
แนวคิด: DFA ต้อง "ตัดสินใจ" ก่อนว่าจะรับ ab หรือ aba — แต่ NFA เดาได้!
3 states: \(s\) (start), \(q_1\) (หลัง ab), \(q_2\) (หลัง aba, final)
Transitions: \(s \xrightarrow{a} q_1\), \(q_1 \xrightarrow{b} q_2\), \(q_2 \xrightarrow{a} q_3\) (final ที่ \(q_2\) และ \(q_3\))
ทดสอบ "ab": \((s,ab) \vdash (q_1,b) \vdash (q_2,e)\) → accept ✓
ทดสอบ "aba": \((s,aba) \vdash (q_1,ba) \vdash (q_2,a) \vdash (q_3,e)\) → accept ✓
ผิดบ่อย 1: เข้าใจว่า NFA "ต้องเลือก" ทางที่ถูก — จริงๆ NFA ลองทุกทางพร้อมกัน!
ผิดบ่อย 2: ในการ trace ต้องเขียนทุก config ที่เป็นไปได้ ไม่ใช่แค่ 1 path — ใช้ \(\vdash^*\) เชื่อมทุกสาย
ผิดบ่อย 3: ลืมว่า \(\varepsilon\)-transition ไม่กิน symbol — สายเดินได้แม้ input ยังไม่เดิน
ถามตัวเอง: ทุก DFA เป็น NFA ด้วยหรือไม่?
✅ ใช่! DFA เป็น NFA ชนิดพิเศษ (transition function เป็น subset ของ transition relation แบบ deterministic ทุกคู่มี transition เดียว)
จากห้องเรียน — ความแตกต่าง DFA vs NFA:
• DFA: \(\delta\) เป็น function (one-to-one mapping) → กำหนดผลลัพธ์ได้แน่นอน
• NFA: \(\Delta\) เป็น relation (one-to-many / many-to-many) → ต้อง "เดาทุกทาง"
• NFA มี e-transition (เปลี่ยน state โดยไม่อ่าน input)

สรุป: NFA ยอมรับสตริง iff มีอย่างน้อยหนึ่งเส้นทางที่ไปถึง final state
NFA สำหรับ \((a \cup ab)^*\):
\(M = (\{s,q\}, \{a,b\}, \Delta, s, \{s\})\)
\(\Delta = \{(s,a,q), (q,e,s), (q,b,s)\}\)

สังเกต: มี e-transition จาก \(q\) กลับ \(s\) (ไม่ต้องอ่าน input)

NFA → DFA: Powerset Construction ออกสอบทุกชุด

สำหรับทุก NFA มี DFA ที่เท่าเทียมกัน (equivalent) — คือรับภาษาเดียวกัน
ไอเดียหลัก: "รวม universe หลายๆ อันเป็น universe เดียว"
NFA อยู่หลาย state พร้อมกันได้ → DFA ใหม่แต่ละ state ก็คือเซตของ state NFA ที่เป็นไปได้ทั้งหมด ในเวลานั้น!
เรียกว่า "superstate" — 1 superstate = 1 ชุดของ NFA states
ถ้า NFA มี \(n\) states → DFA อาจมีถึง \(2^n\) states (เลยชื่อ "powerset construction")
🎬 อุปมา: หนัง Avengers
NFA = ทีม Avengers หลายคน กระจายไปสู้ในหลายพื้นที่พร้อมกัน
DFA = จับกล้องถ่ายรวม — "ตอนนี้ Avengers อยู่ที่ไหนบ้าง?" → เก็บเป็น 1 snapshot ({Iron Man, Thor, Hulk})
แต่ละ snapshot = 1 superstate — เดินหน้าตาม input พร้อมกันทุกคน

👥 อุปมา: กลุ่มไลน์
NFA state = คนแต่ละคน — DFA state = "กลุ่มไลน์" ที่รวมทุกคนที่ active ตอนนั้น

E-Closure (การปิดแบบ epsilon)

\(E(q) = \{p \mid p \in K \text{ and } (q, e) \vdash_M^* (p, e)\}\)
— เซตของ state ทั้งหมดที่ไปถึงจาก \(q\) ผ่าน e-transition เท่านั้น (รวม \(q\) เอง)
E-Closure = "ทุกที่ที่เดินฟรีถึงได้"
ก่อนอ่าน input ตัวใหม่ ให้ "แผ่" ไปทุก state ที่ ε-transition พาไปถึง — เพราะเดินฟรี ไม่เสีย input
วิธีคิด: จาก \(q\) — เจอ ε-lane ไปที่ไหนได้ต่อ? ตามไปเรื่อยๆ จนตัน (fixed point) → นั่นคือ E(q)
🚇 อุปมา: รถไฟใต้ดินฟรี
สมมติในเมืองมีรถไฟใต้ดินฟรี (ε-transition) ที่วิ่งเชื่อมสถานีบางที่
คุณอยู่สถานี \(q\) → E(q) = "ทุกสถานีที่ไปถึงได้ฟรี" (ไม่ต้องใช้ token / input)
ก่อนจะเดินขึ้นรถเมล์ (transition ด้วย symbol) → คุณควรใช้รถไฟฟรีให้เต็มที่ก่อน!

การสร้าง DFA \(M' = (K', \Sigma, \delta, s', F')\)

1
\(K' = 2^K\) — แต่ละ state ของ DFA ใหม่เป็นเซตของ states (superstate)
2
\(s' = E(s)\) — initial state ใหม่ = E-closure ของ initial state เดิม
3
\(\delta(Q, \sigma) = \bigcup_{q \in Q} \{E(p) \mid (q, \sigma, p) \in \Delta\}\) — transition: รวม E-closure ของทุกปลายทาง
4
\(F' = \{Q \subseteq K \mid Q \cap F \neq \emptyset\}\) — final state = superstate ที่มี final state เดิมอยู่ข้างใน
ข้อสอบ Practice 1, Q14: แปลง NFA ที่มี \(E(q_0) = \{q_0, q_1\}\)
Step 1: \(q'_0 = E(q_0) = \{q_0, q_1\}\)

Step 2: หา \(\delta'(q'_0, a)\):
จาก \(q_0\) อ่าน \(a\) ไปได้ \(q_0\) → \(E(q_0) = \{q_0, q_1\}\)
จาก \(q_1\) อ่าน \(a\) ไปได้ ... (ดูจาก NFA)
รวม E-closure ทั้งหมด → ได้ superstate ใหม่

Step 3: \(\delta'(\delta'(q'_0, a), b) = \delta'(\{q_0, q_1\}, b)\)
จาก \(q_0\) อ่าน \(b\) → \(q_0\) → \(E(q_0) = \{q_0, q_1\}\)
จาก \(q_1\) อ่าน \(b\) → \(q_2, q_4\) → \(E(q_2) \cup E(q_4)\)
ผลลัพธ์: \(\{q_0, q_1, q_2, q_4\}\)
จากห้องเรียน (Powerset Construction ตั้งชื่อโดย Scott and Dana, 1958):
• แต่ละ state ของ DFA ใหม่เรียกว่า "superstate"
• E-Closure คำนวณโดย iterate จนไม่เปลี่ยนแปลง (convergence)

DFA Complement — สลับ Final States ออกสอบ

ให้ DFA \(M = (K, \Sigma, \delta, s, F)\)
สร้าง \(M' = (K, \Sigma, \delta, s, K - F)\) — สลับ final กับ non-final
แล้ว \(L(M') = \Sigma^* - L(M)\) = complement ของ L(M)
ข้อสอบ Practice 1, Q12: ให้ DFA \(M\) มี \(F = \{q_0, q_1, q_2\}\)
สร้าง \(M'\) ที่ \(L(M') = \Sigma^* - L(M)\)
เปลี่ยน final states เป็น \(F' = K - F = \{q_3\}\)
DFA \(M'\) เหมือน \(M\) ทุกอย่าง ยกเว้น final state เปลี่ยนเป็น \(\{q_3\}\)
→ \(L(M')\) = ทุกสตริงที่ \(M\) ไม่ยอมรับ
ข้อสอบ Practice 4, Q13 — กรณีพิเศษ:
ถ้า \(M' = (K, \Sigma, \delta, s, K-F \cup \{s\})\) (complement + เพิ่ม s เป็น final)
จะได้ \(L(M) \cup L(M') = \Sigma^*\) ✅
แต่ \(L(M') \neq \overline{L(M)}\)! เพราะ s อาจเป็น final ทั้งใน M และ M'
→ ทำให้ \(L(M) \cap L(M') \neq \emptyset\) (ไม่ disjoint)
ใช้ Complement พิสูจน์ว่าภาษาไม่ regular:
ถ้า \(L\) regular → \(\overline{L}\) regular (closure)
ดังนั้นถ้า \(\overline{L}\) ไม่ regular → \(L\) ก็ไม่ regular! (contrapositive)

FA ↔ Regular Language — Kleene's Theorem

Kleene's Theorem: ภาษา \(L\) เป็น regular iff \(L\) ถูกรับรองโดย finite automaton

ทิศทาง 1: Regular → FA

ทุก regular language มี regular expression → สร้าง NFA จาก regex ได้:

  • \(\emptyset\) → NFA ที่ไม่มี final state
  • \(\{a\}\) → NFA: \(q_0 \xrightarrow{a} q_1\) (final)
  • \(L_1 \cup L_2\) → NFA ใหม่: e-transition ไปยัง NFA ของ \(L_1\) และ \(L_2\)
  • \(L_1 \cdot L_2\) → NFA ของ \(L_1\) ต่อด้วย \(L_2\) ผ่าน e-transitions
  • \(L^*\) → เพิ่ม e-transition loop กลับ initial state

ทิศทาง 2: FA → Regular

จากห้องเรียน (FSA → RL):
ใช้ State Elimination:
1. Eliminate states ทีละตัว
2. แทนที่ด้วย regex บน edges
3. จนเหลือ start state กับ final state → regex บน edge = คำตอบ

หรือใช้สูตร \(R(i,j,k)\):
\(R(i,j,k) = R(i,j,k-1) \cup R(i,k,k-1) \cdot R(k,k,k-1)^* \cdot R(k,j,k-1)\)

Pumping Theorem — ตัวอย่างเพิ่มเติม

พิสูจน์: \(\{\omega \in \{a,b\}^* \mid \omega \text{ มี a กับ b จำนวนเท่ากัน}\}\) ไม่เป็น regular
สมมติ \(L\) เป็น regular → มี pumping length \(n\)
เลือก \(\omega = a^n b^n \in L\) (มี a, b จำนวนเท่ากัน, ความยาว \(2n \geq n\))
เขียน \(\omega = xyz\) ที่ \(|xy| \leq n\) → \(xy\) อยู่ในส่วน \(a^n\) → \(y = a^j, j \geq 1\)
Pump \(k=2\): \(xy^2z = a^{n+j}b^n\) แต่ \(n+j \neq n\) → จำนวน a ≠ จำนวน b → \(xy^2z \notin L\)
ขัดแย้ง! ∴ \(L\) ไม่เป็น regular ∎
พิสูจน์: \(\{a^nb^nc^n \mid n \geq 0\}\) ไม่เป็น regular
เหมือนกับ \(\{a^nb^n\}\) เพราะ \(|xy| \leq n\) → \(y\) อยู่ในส่วน \(a^n\) ทั้งหมด
Pump \(k=0\): \(xz = a^{n-j}b^nc^n\) แต่ \(n-j < n\) → จำนวน a < b = c → ไม่อยู่ใน L
∴ ไม่เป็น regular ∎
Pumping Theorem ใช้พิสูจน์อะไร?
• ✅ ใช้พิสูจน์ว่าภาษาไม่เป็น regular (proof by contradiction)
• ❌ ไม่สามารถใช้พิสูจน์ว่าภาษาเป็น regular!
(มีภาษาที่ไม่ regular แต่ผ่าน pumping condition ได้)

Equivalence Relation ระหว่าง States

\(L'_p = \{\omega \mid \exists f \in F: (p, \omega) \vdash^* (f, e)\}\) — ภาษาที่ state \(p\) ยอมรับ
\(p \equiv q\) iff \(L'_p = L'_q\) — "p กับ q ทำหน้าที่เหมือนกัน"
\(p \equiv_n q\) iff \(L'_{p,n} = L'_{q,n}\) — "เหมือนกันสำหรับ strings ยาวไม่เกิน n"

Lemma สำคัญ

\(p \equiv_{n+1} q\) iff:
1. \(p \equiv_n q\) (เหมือนกันในระดับ n)
2. สำหรับทุก \(a \in \Sigma\): \(\delta(p,a) \equiv_n \delta(q,a)\) (successor ก็เหมือนกัน)

คุณสมบัติ Closure ของ Regular Languages ออกสอบบ่อย

ภาษาที่ FA รับรองได้ (= regular languages) ปิดภายใต้ (closed under):
1. ✅ Union — \(L(M_1) \cup L(M_2)\) ก็ regular
2. ✅ Concatenation — \(L(M_1) \cdot L(M_2)\) ก็ regular
3. ✅ Kleene star — \(L(M_1)^*\) ก็ regular
4. ✅ Complementation — \(\overline{L(M_1)}\) ก็ regular (สลับ final/non-final ใน DFA)
5. ✅ Intersection — \(L(M_1) \cap L(M_2)\) ก็ regular (ใช้ DeMorgan หรือ product construction)
ภาษา \(L\) เป็น regular iff \(L\) ถูกรับรองโดย finite automaton
DFA Complement: ให้ DFA \(M\) → สร้าง \(M'\) โดยสลับ final states กับ non-final states
\(L(M') = \Sigma^* - L(M)\)
ข้อสอบ Practice 4, Q13: ให้ \(M' = (K, \Sigma, \delta, s, K - F \cup \{s\})\) คือ DFA complement + เพิ่ม \(s\) เป็น final
\(L(M) \cup L(M') = \Sigma^*\) ✅ แต่ \(L(M') \neq \Sigma^* - L(M)\) (เพราะ \(s\) อาจเป็น final ทั้งสองที่!)

Pumping Theorem ออกสอบเป็นข้อพิสูจน์

ให้ \(L\) เป็น regular language มีจำนวนเต็ม \(n > 0\) ที่ทุกสตริง \(\omega \in L\) ที่ \(|\omega| \geq n\) สามารถเขียนเป็น \(\omega = xyz\) โดย:
1. \(y \neq e\) (ส่วน y ต้องมีอักษรอย่างน้อย 1 ตัว)
2. \(|xy| \leq n\) (ส่วน xy อยู่ใน n ตัวแรก)
3. \(xy^kz \in L\) สำหรับทุก \(k \geq 0\) (ปั๊ม y กี่รอบก็ยังอยู่ใน L)
Pumping Theorem = "หลัก Pigeonhole ของ DFA"
ทำไม pump ได้? เพราะ DFA มี state จำกัด! ถ้าสตริงยาวกว่าจำนวน state → ต้องวนซ้ำ state เดิมอย่างน้อย 1 ตัว
ส่วนที่วนซ้ำนั้นคือ \(y\) — ไป loop กี่รอบก็ยังยอมรับ (เหมือน hamster วิ่งบน wheel)

Pumping Theorem ใช้ทำอะไร? ใช้ พิสูจน์ว่าภาษาไม่ regular — ถ้าเจอสตริงที่ pump แล้วออกจากภาษา = ไม่ regular
🍿 อุปมา: ต่อลูกโป่ง
สตริงยาวใน regular language = ลูกโป่งที่มี "ส่วนกลาง \(y\) เป่าลมเพิ่มได้"
• ค่อยๆ เป่า \(y\) ซ้ำ 1, 2, 3 รอบ → ยังเป็นลูกโป่งใน L
• ลด \(y\) ออก (k=0) → ยังคงเป็นลูกโป่ง
👉 ถ้าเป่าแล้วมัน "ระเบิด" (ออกจาก L) → ภาษานี้ไม่ใช่ regular!

Context-Free Grammar (CFG) — นิยาม

CFG คือ 4-tuple \(G = (V, \Sigma, R, S)\) โดย:
• \(V\) = alphabet (สัญลักษณ์ทั้งหมด)
• \(\Sigma \subset V\) = terminals (สัญลักษณ์ปลายทาง — ตัวอักษรจริง)
• \(V - \Sigma\) = nonterminals (สัญลักษณ์กลาง — ตัวแปร)
• \(R \subseteq (V - \Sigma) \times V^*\) = rules (กฎการผลิต)
• \(S \in V - \Sigma\) = start symbol
CFG = "สูตรทำประโยค" ที่แตกได้ทีละส่วน
คิดว่ามีคำ 2 ประเภท:
• Terminal (ตัวจริง) = คำสุดท้ายที่จะออกมา เช่น \(a, b, x, +\) — ไม่แตกต่อได้
• Nonterminal (ตัวสมมุติ) = "ตัวแทน" ที่ต้องแตกเป็นอย่างอื่น เช่น \(S, E, T\)
กฎ \(A \to u\) = "แทน A ด้วย u" — เอาไปใช้ตรงไหนก็ได้ที่เจอ A (ไม่ต้องดูว่าอยู่ข้างๆ อะไร → "context-free")
เริ่มจาก \(S\) → แตกไปเรื่อยๆ จนเหลือแค่ terminal → นั่นคือสตริงในภาษา!
🌳 อุปมา: ต้นไม้ครอบครัว
Nonterminal = "ตำแหน่งในครอบครัว" (พ่อ, แม่, ลูก) — Terminal = ชื่อจริง
กฎ: "พ่อ → ปู่ ตัวเอง" หมายถึง ทุกครั้งที่พูดถึง "พ่อ" คุณสามารถแทนได้ด้วย "ปู่ ตัวเอง"
เริ่มจากตำแหน่งบนสุด → แตกลงมาเรื่อยๆ → ได้ชื่อจริงทั้งหมด

"เมื่อวาน [ชื่อ] ไปที่ [สถานที่] แล้วเจอ [สัตว์]" — [xxx] คือ nonterminal, ชื่อจริงคือ terminal
ตัวอย่าง: Grammar สำหรับ \(a^n b^n\)
กฎ: \(S \to aSb\)  |  \(S \to e\)
Derivation ของ "aabb":
\(S \Rightarrow aSb\) (ใช้กฎ 1)
\(\Rightarrow aaSbb\) (ใช้กฎ 1 อีก)
\(\Rightarrow aabb\) (ใช้กฎ 2: S → e)
สรุป: "aabb" \(\in L(G)\) ✓
ผิดบ่อย: ลืมกฎ base case! \(S \to aSb\) อย่างเดียว → derivation ไม่มีวันจบ! ต้องมี \(S \to e\) หรือกฎอื่นที่ end

เขียน \(A \to u\) สำหรับกฎ \((A, u) \in R\)

\(\omega \Rightarrow_G \upsilon\) iff มีกฎ \(A \to u\) ที่ \(\omega = xAy\) และ \(\upsilon = xuy\)

Derivation: \(\omega_0 \Rightarrow \omega_1 \Rightarrow ... \Rightarrow \omega_n\)

\(L(G) = \{\omega \in \Sigma^* \mid S \Rightarrow^* \omega\}\) = ภาษาที่ \(G\) สร้าง

จากห้องเรียน: CFG "ไม่ขึ้นบริบท" หมายถึง กฎ \(A \to u\) ใช้ได้ทุกที่ที่พบ \(A\) โดยไม่ต้องดูว่ามีอะไรล้อมรอบ (context ไม่สำคัญ)
Grammar สำหรับ arithmetic expressions:
\(\Sigma = \{x, +, *, (, )\}\), \(V = \Sigma \cup \{E, T, F\}\)
\(R = \{E \to E+T, \; E \to T, \; T \to T*F, \; T \to F, \; F \to (E), \; F \to x\}\)

Derivation ของ (x):
\(E \Rightarrow T \Rightarrow F \Rightarrow (E) \Rightarrow (T) \Rightarrow (F) \Rightarrow (x)\)

Regular ⊂ Context-Free & CFG Design

ทุก regular language เป็น context-free language (แต่กลับกันไม่จริง!)
Proof: ให้ DFA \(M = (K, \Sigma, \delta, s, F)\) สร้าง CFG \(G = (V, \Sigma, R, S)\):
• \(V = K \cup \Sigma\), \(S = s\)
• กฎ: \(P \to aQ\) เมื่อ \(\delta(P, a) = Q\), และ \(P \to e\) เมื่อ \(P \in F\)
ทุก accepted computation ของ DFA สามารถจำลองเป็น leftmost derivation ใน \(G\) ∎

ตัวอย่าง CFL ที่ไม่ใช่ Regular (สำคัญมาก)

ภาษาGrammarทำไมไม่ regular
\(\{a^n b^n \mid n \geq 0\}\)\(S \to aSb \mid e\)ต้อง "จำ" จำนวน a เพื่อจับคู่ b
\(\{a^n b^{2n} \mid n \geq 0\}\)\(S \to aSbb \mid e\)ต้อง "จำ" จำนวน a → ผลิต b สองเท่า
\(\{\omega\omega^R \mid \omega \in \{a,b\}^*\}\)\(S \to aSa \mid bSb \mid e\)ต้อง "จำ" ลำดับตัวอักษร
Balanced parentheses\(S \to (S) \mid SS \mid e\)ต้อง "นับ" ว่าเปิดวงเล็บกี่ตัว

เทคนิคออกแบบ CFG (จากห้องเรียน)

1. Recursive structure: หารูปแบบ recursive เช่น \(a^nb^n\) = a + (ตรงกลาง) + b
2. Union decomposition: ถ้า \(L = L_1 \cup L_2\) ให้ \(S \to S_1 \mid S_2\)
3. Concatenation: ถ้า \(L = L_1 \cdot L_2\) ให้ \(S \to S_1 S_2\)
4. Kleene star: ถ้า \(L = L_1^*\) ให้ \(S \to S_1 S \mid e\)

ประเภทของ Derivation

Leftmost Derivation (\(\Rightarrow_L\))

แทนที่ nonterminal ตัวซ้ายสุดก่อนเสมอ
\(E \Rightarrow_L E + T \Rightarrow_L T + T \Rightarrow_L F + T \Rightarrow_L x + T \Rightarrow_L x + F \Rightarrow_L x + x\)

Rightmost Derivation (\(\Rightarrow_R\))

แทนที่ nonterminal ตัวขวาสุดก่อนเสมอ
\(E \Rightarrow_R E + T \Rightarrow_R E + F \Rightarrow_R E + x \Rightarrow_R T + x \Rightarrow_R F + x \Rightarrow_R x + x\)
ข้อความต่อไปนี้เทียบเท่ากัน:
1. \(A \Rightarrow^* \omega\)
2. มี parse tree ที่มี root \(A\) และ yield \(\omega\)
3. \(A \Rightarrow_L^* \omega\) (leftmost derivation)
4. \(A \Rightarrow_R^* \omega\) (rightmost derivation)
จากห้องเรียน: "S = sentence" — start symbol เหมือน "ประโยค" ที่จะถูก "แจกแจง" ออกเป็นส่วนย่อยๆ (mother → daughter nodes)

Parse Trees & Ambiguity ออกสอบบ่อย

Parse Tree (ต้นไม้การแจกแจง)

แสดง derivation เป็นโครงสร้างต้นไม้:

  • Root: start symbol (หรือ nonterminal ที่เริ่มต้น)
  • Internal nodes: nonterminals — เรียกว่า mother
  • Children: ลูกของ mother — เรียกว่า daughter
  • Leaves (yield): terminals ที่เรียงจากซ้ายไปขวา = สตริงผลลัพธ์

Ambiguity (ความกำกวม)

Grammar \(G\) เป็น ambiguous iff มีสตริง \(\omega \in L(G)\) ที่มี parse tree มากกว่า 1 ต้น (หรือ leftmost derivation มากกว่า 1 แบบ)
G₁ (unambiguous): \(E \to E+T \mid T\), \(T \to T*F \mid F\), \(F \to (E) \mid x\)
G₂ (ambiguous): \(E \to E+E \mid E*E \mid (E) \mid x\)

สตริง \(x + x * x\) :
• ใน G₁: parse tree เดียว (precedence: * > + ถูกบังคับโดยโครงสร้าง)
• ใน G₂: มี 2 parse trees — \((x+x)*x\) หรือ \(x+(x*x)\) — กำกวม!
Ambiguity เป็นคุณสมบัติของ Grammar ไม่ใช่ Language!
ภาษาเดียวกันอาจมี grammar ที่ ambiguous และ unambiguous ได้
แต่ถ้าทุก grammar สำหรับภาษา L เป็น ambiguous → L เรียกว่า inherently ambiguous

Pushdown Automata (PDA) — นิยาม ออกสอบบ่อย

PDA = NFA + "สมุดบันทึกช่วยจำ" (stack)
NFA มีปัญหา: "จำ" ไม่ได้ (เพราะ state จำกัด) → รับภาษาเช่น \(a^n b^n\) ไม่ได้
PDA แก้ปัญหา: เพิ่ม stack — ช่วยจำได้เท่าที่ push เข้าไป (unlimited!)
Stack = "จานซ้อน" = LIFO (Last In, First Out) — เข้าหลังออกก่อน
🍽️ อุปมา: จานล้างในร้านอาหาร
Stack ก็เหมือนกองจานที่ล้างเสร็จ:
• Push (วาง) — วางจานใหม่บนสุด
• Pop (หยิบ) — หยิบจานบนสุดออก
• Top — ดูว่าจานบนสุดเป็นอะไร

🎮 อุปมา: Undo Stack ในเกม/โปรแกรม
กด Ctrl+Z = pop action ล่าสุด → ย้อน state
กดทำอะไรใหม่ = push action ใหม่

🎒 อุปมา: กระเป๋าใส่ของ (แบบใส่จากด้านบน)
ใส่ของทีละชิ้น → ของที่ใส่ทีหลังต้องหยิบออกก่อน

💡 ทำไม stack ช่วย \(a^n b^n\)?
Phase 1: อ่าน 'a' → push 'a' 1 ตัว → ทำซ้ำ n รอบ (stack มี n ตัว)
Phase 2: อ่าน 'b' → pop 'a' 1 ตัว → ทำซ้ำ n รอบ (stack ว่าง)
ถ้า b น้อยกว่า/มากกว่า a → stack ไม่ว่าง = reject!
PDA = NFA + Stack! — 6-tuple \(M = (K, \Sigma, \Gamma, \Delta, s, F)\)
• \(K\) = เซตจำกัดของ states
• \(\Sigma\) = input alphabet
• \(\Gamma\) = stack alphabet (สัญลักษณ์ที่ใช้ใน stack)
• \(s \in K\) = initial state
• \(F \subseteq K\) = final states
• \(\Delta \subseteq (K \times (\Sigma \cup \{e\}) \times \Gamma^*) \times (K \times \Gamma^*)\) = transition relation

การอ่าน Transition

transition \(((p, a, \alpha), (q, \beta))\) หมายถึง:

1
อยู่ที่ state \(p\)
2
อ่าน input \(a\) (หรือ \(e\) = ไม่อ่าน)
3
Pop \(\alpha\) ออกจาก top ของ stack (ต้อง match!)
4
เปลี่ยนเป็น state \(q\)
5
Push \(\beta\) ลง stack

Configuration & Acceptance

Configuration: \((q, \omega, \upsilon)\) = (state ปัจจุบัน, input ที่เหลือ, stack contents)

Acceptance: \((s, \omega, e) \vdash^* (q, e, e)\) โดย \(q \in F\)

— input หมด + stack ว่าง + อยู่ที่ final state = accepted!

PDA — ตัวอย่างพร้อม Computation Trace

PDA สำหรับ \(L = \{\omega c \omega^R \mid \omega \in \{a,b\}^*\}\):
\(M = (\{s, f\}, \{a,b,c\}, \{a,b\}, \Delta, s, \{f\})\)
\(\Delta = \{ ((s,a,e),(s,a)), ((s,b,e),(s,b)), ((s,c,e),(f,e)), ((f,a,a),(f,e)), ((f,b,b),(f,e)) \}\)

หลักการ:
• Phase 1 (state s): อ่าน input → push ลง stack
• เจอ c: เปลี่ยนเป็น state f (ไม่อ่านจาก stack)
• Phase 2 (state f): pop จาก stack เทียบกับ input
Trace สำหรับ input "abcba":
StepConfiguration (state, input, stack)Action
0\((s, abcba, e)\)อ่าน a, push a
1\((s, bcba, a)\)อ่าน b, push b
2\((s, cba, ba)\)อ่าน c, เปลี่ยน state
3\((f, ba, ba)\)อ่าน b, pop b (match!)
4\((f, a, a)\)อ่าน a, pop a (match!)

ภาษา \(L\) เป็น context-free iff มี PDA รับรอง \(L\)

CFG → PDA Construction

ให้ CFG \(G = (V, \Sigma, R, S)\) สร้าง PDA ที่จำลอง leftmost derivation:
• Stack เก็บ sentential form ที่เหลือ
• ถ้า top = nonterminal \(A\): เลือกกฎ \(A \to \alpha\) แทนที่ (nondeterministic)
• ถ้า top = terminal \(a\): match กับ input (pop + อ่าน)
• Accept เมื่อ stack ว่างและ input หมด

PDA — ตัวอย่างเพิ่มเติม

PDA สำหรับ \(L = \{a^n b^n \mid n \geq 1\}\):
\(M = (\{q_0, q_1, q_2\}, \{a,b\}, \{a\}, \Delta, q_0, \{q_2\})\)
\(\Delta = \{((q_0, a, e), (q_0, a)), ((q_0, b, a), (q_1, e)), ((q_1, b, a), (q_1, e)), ((q_1, e, e), (q_2, e))\}\)

Trace สำหรับ aabb:
\((q_0, aabb, e) \vdash (q_0, abb, a) \vdash (q_0, bb, aa)\)
\(\vdash (q_1, b, a) \vdash (q_1, e, e) \vdash (q_2, e, e)\) → ACCEPT ✅
PDA สำหรับ balanced parentheses \(L = \{w \mid w \text{ has matching parens}\}\):
Grammar: \(S \to (S) \mid SS \mid e\)
PDA idea:
• เจอ '(' → push '(' ลง stack
• เจอ ')' → pop '(' จาก stack (ถ้า stack ว่าง → reject)
• input หมด + stack ว่าง → accept
• input หมด + stack ไม่ว่าง → reject
จากห้องเรียน (cfg-annotated): PDA = NFA + Stack
Stack ทำให้ PDA "จำ" ได้มากกว่า FA — สามารถนับจำนวน, จับคู่ brackets, ตรวจ palindrome ได้

CFG — ตัวอย่างออกแบบ

\(L = \{a^i b^j \mid i \neq j\}\):
แยกเป็น \(L = \{a^i b^j \mid i > j\} \cup \{a^i b^j \mid i < j\}\)
\(S \to S_1 \mid S_2\)
\(S_1 \to aS_1b \mid aA\), \(A \to aA \mid a\) (i > j: a เหลือ)
\(S_2 \to aS_2b \mid bB\), \(B \to bB \mid b\) (i < j: b เหลือ)
\(L = \{a^i b^j c^k \mid i = j \text{ or } j = k\}\):
\(S \to S_1 \mid S_2\)
\(S_1 \to AB\) โดย \(A \to aAb \mid e\) (a=b), \(B \to cB \mid e\) (c อะไรก็ได้)
\(S_2 \to CD\) โดย \(C \to aC \mid e\) (a อะไรก็ได้), \(D \to bDc \mid e\) (b=c)
ข้อระวัง: \(\{a^i b^j c^k \mid i = j \text{ and } j = k\} = \{a^n b^n c^n\}\) ← ภาษานี้ไม่ใช่ CFL!
"or" → CFG ทำได้ (Union), "and" → CFG อาจทำไม่ได้!

Chomsky Normal Form (CNF) ออกสอบบ่อย

Chomsky Normal Form (CNF): CFG ที่ทุกกฎมีรูปแบบ:
• \(A \to BC\) (สอง nonterminals) หรือ
• \(A \to a\) (terminal ตัวเดียว)
ไม่มี e-rules, ไม่มี unit rules, ไม่มีกฎที่มีมากกว่า 2 ตัวทางขวา
CNF = "ทำ Grammar ให้เป็น Binary Tree"
ทำไมต้องแปลง? เพราะ parse tree ของ CNF จะเป็น binary tree เสมอ → parse ได้เร็ว (\(O(n^3)\)) ด้วย CYK algorithm
CNF ไม่ได้ทำให้ภาษาเปลี่ยน — แค่เปลี่ยนรูปแบบกฎให้เรียบง่ายลง (ยกเว้นภาษาที่มี ε ในตัว)
🌳 อุปมา: จัดต้นไม้ครอบครัวใหม่
Grammar ปกติ = ต้นไม้ที่พ่อแม่มีลูกกี่คนก็ได้
CNF = ต้นไม้ที่พ่อแม่มีลูกได้แค่ 2 คน เสมอ (เหมือน binary tree)

🍞 อุปมา: อบขนมปัง
CNF = recipe มาตรฐาน "ต้องเป็นแป้ง+น้ำ (สองอย่าง)" หรือ "ต้องเป็นเกลือ (อย่างเดียวเลย)"
ห้ามใส่ 3 อย่างพร้อมกัน — แต่ก็ทำขนมปังทุกแบบได้ (แค่ต้องแตก step ให้ละเอียดขึ้น)
ผิดบ่อย: Order ของ 4 steps สำคัญ! ต้องทำตามลำดับ 1→2→3→4:
1. Binarize ก่อน (เพราะ step อื่น assume binary form)
2. หา nullable (ต้องหาให้ครบก่อน)
3. ลบ e-rules (ใช้ nullable set)
4. ลบ unit rules สุดท้าย (เพราะ step ก่อนหน้าอาจสร้าง unit เพิ่ม)

ขั้นตอนแปลงเป็น CNF (4 steps)

1
Binarize: แปลงกฎยาว \(A \to B_1B_2...B_n\) (n > 2) เป็นกฎคู่:
\(A \to B_1 A_1\), \(A_1 \to B_2 A_2\), ..., \(A_{n-2} \to B_{n-1} B_n\)
2
Find nullable: หา \(E = \{A \mid A \Rightarrow^* e\}\) — nonterminals ที่ derive ไปเป็น empty string ได้
คำนวณ iteratively: ถ้า \(A \to B_1...B_n\) และทุก \(B_i \in E\) แล้ว \(A \in E\)
3
Remove e-rules: ลบกฎ \(A \to e\) ทุกตัว แล้วเพิ่มกฎทดแทน:
ถ้า \(B \to \alpha A \beta\) และ \(A \in E\) → เพิ่ม \(B \to \alpha \beta\)
4
Remove unit rules: ลบกฎ \(A \to B\) (unit rule) แล้ว:
ถ้า \(B \to \alpha\) → เพิ่ม \(A \to \alpha\) (bypass ตัวกลาง)
ตัวอย่าง: แปลง Grammar เป็น CNF (จากห้องเรียน cfg-annotated)
Grammar เดิม: \(S \to aSb \mid e\)

Step 1 (Binarize): \(S \to aSb\) มี 3 ตัว → \(S \to aT, T \to Sb\)
ยังมี terminal ผสม → แทน \(a\) ด้วย \(A\), \(b\) ด้วย \(B\):
\(S \to AT, T \to SB, A \to a, B \to b\)
Step 2 (Nullable): \(E = \{S\}\) (เพราะ \(S \to e\))
Step 3 (Remove e): \(T \to SB\), S nullable → เพิ่ม \(T \to B\)
\(S \to AT\), — ลบ \(S \to e\)
Step 4 (Remove unit): \(T \to B\) เป็น unit rule → แทนด้วย \(T \to b\)

CNF สุดท้าย:
\(S \to AT, T \to SB, T \to b, A \to a, B \to b\)
(Note: ภาษาเปลี่ยนจาก \(\{a^nb^n \mid n \geq 0\}\) เป็น \(\{a^nb^n \mid n \geq 1\}\) เพราะตัด e-rule)

CYK Parsing Algorithm ออกสอบบ่อย

CYK (Cocke-Younger-Kasami): ให้ CNF grammar \(G\) และ string \(\omega = x_1...x_n\)
คำนวณ \(N[i,j] = \{A \mid A \Rightarrow^* x_i...x_j\}\) — "nonterminals ที่ derive ได้ substring จากตำแหน่ง i ถึง j"
\(\omega \in L(G)\) iff \(S \in N[1,n]\)
CYK = "ตอบทีละส่วนเล็ก แล้วรวมเป็นใหญ่" (Dynamic Programming)
คิดว่ากำลังต่อจิ๊กซอว์:
1. เริ่มด้วยชิ้นเล็กสุด (1 ตัวอักษร) → หา nonterminal ที่ผลิตมันได้
2. รวม 2 ชิ้นเล็กเป็นชิ้นใหญ่ขึ้น (2 ตัวอักษร) → หา A → BC ที่ตรงกัน
3. รวมต่อไปเรื่อยๆ จนได้ทั้งสตริง
4. ถ้า \(S\) อยู่ในตำแหน่ง [1,n] (ทั้งสตริง) → yes! สตริงอยู่ในภาษา
🧩 อุปมา: ต่อจิ๊กซอว์
ต่อชิ้นเล็กก่อน → รวมเป็นชิ้นใหญ่ → รวมเป็นภาพเต็ม
แต่ละช่องในตาราง CYK = "ส่วนที่ต่อได้ถึงตรงนี้"

🏗️ อุปมา: สร้างตึก LEGO
บล็อค LEGO ขนาด 1 → รวมเป็นขนาด 2 → รวมเป็นขนาด 3 → ... → รวมเป็นตึกทั้งตัว
ต้องรู้ว่า "รวม 2 บล็อคขนาด i กับ j ได้เป็นบล็อคขนาด i+j" (นี่คือกฎ CFG)

💰 อุปมา: ทอนเงิน
เหมือน "จะทอน 100 บาท ด้วยเหรียญ ต้องใช้ยังไง" — คิดว่า 100 = 50+50 หรือ 90+10 → subproblem แต่ละแบบ
ตัวอย่าง CYK ทีละช่อง — Grammar: \(S \to AB\), \(A \to a\), \(B \to b\), input = "ab"
🔹 \(N[1,1]\) = ? → หา nonterm ที่ผลิต 'a' → \(\{A\}\)
🔹 \(N[2,2]\) = ? → หา nonterm ที่ผลิต 'b' → \(\{B\}\)
🔹 \(N[1,2]\) = ? → หา A → BC ที่ \(B \in N[1,1], C \in N[2,2]\) → S → AB match! → \(\{S\}\)
ผลลัพธ์: \(S \in N[1,2]\) → "ab" \(\in L(G)\) ✓
ผิดบ่อย: ต้องแปลง Grammar เป็น CNF ก่อน ใช้ CYK — CYK ทำงานกับ CNF เท่านั้น!
ผิดบ่อย 2: ต้องเช็คทุก split point \(s\) ระหว่าง \(i\) กับ \(j\) — ไม่ใช่แค่ตรงกลาง

วิธีคำนวณ (Bottom-up)

1
Base case: \(N[i,i] = \{A \mid A \to x_i \in R\}\) — หา nonterminal ที่ produce terminal ตัวนั้น
2
Recursive case: \(N[i,j] = \{A \mid A \to BC, B \in N[i,s], C \in N[s+1,j]\}\) สำหรับบาง \(i \leq s < j\)
— ลองแบ่ง substring ทุกจุด แล้วหา nonterminal ที่ produce ส่วนซ้าย + ส่วนขวา
จากห้องเรียน (bottom-up parsing):
เริ่มจากฐาน (single characters) แล้วค่อยๆ สร้างขึ้นไป — "อิฐก่อจากพื้น"
ตารางสามเหลี่ยม: แถวล่างสุด = ตัวอักษรทีละตัว, แถวบนสุด = สตริงทั้งหมด
ตัวอย่าง CYK: \(G: S \to AB, A \to a, B \to b\), ตรวจ \(\omega = ab\)
\(N[1,1] = \{A\}\) (เพราะ \(A \to a\))
\(N[2,2] = \{B\}\) (เพราะ \(B \to b\))
\(N[1,2]\): ลองแบ่งที่ \(s=1\): \(B \in N[1,1] = \{A\}\), \(C \in N[2,2] = \{B\}\)
มีกฎ \(S \to AB\)? ✅ → \(N[1,2] = \{S\}\)
\(S \in N[1,2]\) → \(ab \in L(G)\) ✅

Pumping Theorem สำหรับ CFL

ให้ \(G\) เป็น CFG มีจำนวน \(n\) ที่ทุก \(\omega \in L(G)\) ที่ \(|\omega| > n\) เขียนเป็น \(\omega = uvxyz\) โดย:
• \(v \neq e\) หรือ \(y \neq e\) (อย่างน้อยหนึ่งตัวไม่ว่าง)
• \(uv^kxy^kz \in L(G)\) สำหรับทุก \(k \geq 0\)
พิสูจน์ \(\{a^nb^nc^n\}\) ไม่เป็น CFL:
สมมติ CFL → มี pumping length \(n\)
เลือก \(\omega = a^nb^nc^n\), เขียน \(\omega = uvxyz\) โดย \(vy \neq e\)
Case 1: ถ้า \(v\) หรือ \(y\) มีตัวอักษรมากกว่า 1 ชนิด → pump แล้วลำดับเสีย → ไม่อยู่ใน L
Case 2: ถ้า \(v, y\) มีตัวอักษรชนิดเดียว → pump แล้วจำนวนบางตัวเพิ่มแต่บางตัวไม่เพิ่ม → ไม่เท่ากัน → ไม่อยู่ใน L
ทั้งสองกรณีขัดแย้ง! ∎

🧑‍🏫 อุปมา: ครูตรวจข้อสอบ
ครูอ่านทีละข้อ (head), จำว่าคะแนนสะสมเท่าไร (state), เขียนคะแนนลง (write), เลื่อนไปข้อต่อไป (R)
เมื่อครบทุกข้อ → รู้ผลรวม (accept/reject)
จากห้องเรียน: TM = "Assembler ยุค 1930s" — memory = tape, program = instruction set, state register = finite control
TM = 5-tuple \(M = (K, \Sigma, \delta, s, H)\)
• \(K\) = เซตจำกัดของ states
• \(\Sigma\) = alphabet (มี blank \(\sqcup\) และ left-end \(\triangleright\) แต่ไม่มี \(\leftarrow, \rightarrow\))
• \(s \in K\) = initial state
• \(H \subseteq K\) = halting states (ไม่ใช่ final states แต่เป็น "หยุดทำงาน")
• \(\delta: (K-H) \times \Sigma \to K \times (\Sigma \cup \{\leftarrow, \rightarrow\})\) = transition function

ข้อจำกัด:
• \(\delta(q, \triangleright) = (p, \rightarrow)\) — เจอ left-end ต้องเลื่อนขวาเสมอ
• ห้ามเขียนทับ \(\triangleright\)

Configuration: \((q, \omega_1 a \omega_2)\) = state q, tape content, head อยู่ที่ a

\(\delta(q, a) = (p, b)\): ถ้า \(b \in \Sigma\) → เขียน b ทับ a; ถ้า \(b = \leftarrow\) → เลื่อนซ้าย; ถ้า \(b = \rightarrow\) → เลื่อนขวา

อัลกอริทึม: "mark and match"
วิธี:
1. ข้าม \(\triangleright\) → ไปขวา
2. หา \(a\) ตัวแรกที่ยังไม่ถูก mark → เขียน \(d\) ทับ
3. เลื่อนขวาข้ามทุก \(a\) ที่เหลือ จนเจอ \(b\) หรือ \(d_b\)
4. หา \(b\) ตัวแรกที่ยังไม่ถูก mark → เขียน \(d\) ทับ
5. เลื่อนกลับซ้ายจนถึง \(\triangleright\) → ทำซ้ำจาก step 2
6. ถ้าไม่มี \(a\) เหลือ: ตรวจว่ามี \(b\) เหลือไหม → ถ้าไม่มี → accept, ถ้ามี → reject

ภาษา Recursive & Recursively Enumerable ออกสอบบ่อย

ต่างกันตรงไหน? — คำตอบสั้น:
• Recursive (Decidable): TM ตอบได้ทั้ง "ใช่" และ "ไม่ใช่" เสมอ — หยุดแน่นอน
• RE (Semidecidable): TM ตอบได้แค่ "ใช่" — ถ้า "ไม่ใช่" อาจวนไม่หยุด!

Recursive ⊂ RE — Recursive คือ RE ที่ "ดีกว่า" (รับประกันตอบได้ 2 ทาง)
🕵️ อุปมา: นักสืบ 2 แบบ
• Recursive = นักสืบเก่ง: รับคดี → ยืนยันได้เสมอ ว่า "คนนี้ผิด" หรือ "คนนี้ไม่ผิด" — จบทุกเคส
• RE = นักสืบธรรมดา: รับคดี → ถ้าเจอหลักฐานคนผิด → บอกได้ "ผิด" — ถ้าคนไม่ผิด → หาหลักฐานไม่เจอต่อไปเรื่อยๆ ตลอดชีวิต (ไม่ตอบ "ไม่ผิด" ได้!)

🔍 อุปมา: การค้นหาใน Google
• Recursive: ค้นแล้ว "เจอ" หรือ "ไม่เจอ" — Google บอกได้เสมอ
• RE: ค้นแล้วเจอ → บอก "เจอ"; ค้นไม่เจอ → Google กำลังโหลด...ต่อไป...ตลอดกาล 😱

🎮 อุปมา: การผ่านเกม
• Recursive: เกมที่มี win screen และ game over screen — จบได้ 2 ทาง
• RE: เกมที่ถ้าชนะได้ → ขึ้น win screen; ถ้าแพ้ → เล่นไปเรื่อยๆ ไม่จบ (softlock)
Recursive language (decidable): \(L\) ถูก decide โดย TM \(M\) iff:
• \(\omega \in L\) → \(M\) accepts \(\omega\) (halt ที่ state \(y\))
• \(\omega \notin L\) → \(M\) rejects \(\omega\) (halt ที่ state \(n\))
— M หยุดเสมอ ไม่ว่า input จะเป็นอะไร! (total function)
Recursively Enumerable (RE / semidecidable): \(L\) ถูก semidecide โดย TM \(M\) iff:
• \(\omega \in L\) → \(M\) halts บน \(\omega\)
• \(\omega \notin L\) → \(M\) อาจ loop ตลอดกาล! (ไม่หยุด)
— M อาจไม่หยุดสำหรับ input ที่ไม่อยู่ในภาษา

ความสัมพันธ์ระหว่าง Recursive, RE, และ non-RE

ข้อเท็จจริงสำคัญ:
1. Recursive ⊂ RE ⊂ All Languages
2. ถ้า \(L\) recursive → \(\overline{L}\) ก็ recursive
3. ถ้า \(L\) และ \(\overline{L}\) เป็น RE ทั้งคู่ → \(L\) เป็น recursive
4. ทุก regular language เป็น recursive
5. ทุก context-free language เป็น recursive
6. มีภาษาที่ไม่เป็น RE (เพราะมีภาษา uncountably many แต่ TM มี countably many)
ข้อระวัง:
• RE ≠ Recursive! RE อาจ loop ไม่หยุดสำหรับ input ที่ reject
• Recursive = "safe" (หยุดเสมอ), RE = "risky" (อาจไม่หยุด)

Recursive Functions (ฟังก์ชันเรียกซ้ำ)

ฟังก์ชัน \(f: \Sigma^* \to \Sigma^*\) เป็น recursive iff มี TM \(M\) ที่ compute \(f\):
\((s, \triangleright\sqcup\omega) \vdash^* (h, \triangleright\sqcup f(\omega))\)
— เริ่มจาก input \(\omega\), หยุดพร้อม output \(f(\omega)\) บน tape

ตัวอย่าง: succ(n) — Successor Function

succ(n) = n+1 ใน binary representation:
อัลกอริทึม:
1. ไปขวาจนเจอ blank (หาตัวท้ายสุด)
2. เลื่อนซ้าย 1 ช่อง (อยู่ที่ bit สุดท้าย)
3. ถ้าเป็น 0 → เขียน 1, halt (ไม่มี carry)
4. ถ้าเป็น 1 → เขียน 0, เลื่อนซ้าย (carry!)
5. ทำซ้ำ step 3-4 จน carry หมด
6. ถ้า carry ถึง \(\triangleright\) → shift right ทั้งหมด + เขียน 1

ตัวอย่าง: succ(011) = 100
\(\triangleright\sqcup 011\sqcup\) → ไปขวาสุด → bit สุดท้าย 1 → เขียน 0, carry
→ bit ถัดไป 1 → เขียน 0, carry → bit ถัดไป 0 → เขียน 1
→ \(\triangleright\sqcup 100\sqcup\) ✅

ตัวอย่าง: d(n) = 2n — Double Function

d(n) = 2n ใน unary:
วิธีที่ 1 (Composition): \(d = succ \circ succ \circ ... \circ succ\) (n ครั้ง) — ช้า!

วิธีที่ 2 (Direct): สำหรับ unary \(1^n\):
1. หา 1 ตัวแรก → mark เป็น X
2. ไปขวาจนเจอ blank → เขียน 1 (เพิ่ม 1 ตัว)
3. กลับซ้ายหา X → ไปขวาหา 1 ที่ยังไม่ mark → ทำซ้ำ
4. เมื่อ mark หมดแล้ว → เปลี่ยน X กลับเป็น 1 → halt
ผลลัพธ์: \(1^n → 1^{2n}\) ✅

Multi-tape TM & Church-Turing Thesis

Multi-tape Turing Machine

k-tape TM: \(\delta: (K-H) \times \Sigma^k \to K \times (\Sigma \cup \{\leftarrow, \rightarrow\})^k\)
— อ่าน k tapes พร้อมกัน, เปลี่ยน state, เขียน/เลื่อนบนแต่ละ tape อิสระ
Multi-tape TM = "TM ที่มีสมุดโน้ตหลายเล่ม"
Standard TM มี 1 tape → ต้องเก็บทั้ง input, ผลลัพธ์กลาง, ตัวแปรชั่วคราวใน tape เดียว → เขียนโปรแกรมยาก!
Multi-tape TM มี k tapes → เก็บของแต่ละอย่างในสมุดเล่มต่างกัน → เขียนโปรแกรมง่ายกว่ามาก

ไม่ทรงพลังกว่า! พิสูจน์ได้ว่า 1-tape TM จำลอง k-tape ได้ → ภาษาที่รับได้เท่ากัน (แค่ช้ากว่า)
📓 อุปมา: การทำการบ้านคณิต
• 1-tape TM = การบ้านที่มีสมุดแค่เล่มเดียว — ต้อง cross out, ลบ, เขียนซ้อน
• Multi-tape TM = มีสมุดหลายเล่ม — เล่มโจทย์, เล่มคำนวณ, เล่มคำตอบ → เขียนง่ายกว่าเยอะ!

💻 อุปมา: การใช้คอมพิวเตอร์
Multi-tape เหมือนการเปิดหลาย tab ในโปรแกรม — Tab 1 = โจทย์, Tab 2 = ตัวแปร, Tab 3 = คำตอบ
เร็วกว่า/สะดวกกว่าเปิด tab เดียวสลับไปมา

🎬 อุปมา: ถ่ายหนังหลายกล้อง
1-tape TM = ใช้กล้อง 1 ตัว ต้องหมุนถ่ายทุกมุม
Multi-tape = ใช้กล้อง 5 ตัวถ่ายพร้อมกัน → ตัดต่อทีหลังเร็วกว่า
ตัวอย่าง: 2-tape TM สำหรับ Palindrome (\(\omega \omega^R\)) — จากห้องเรียน tm-annotated
แนวคิด: Tape 1 = input, Tape 2 = temporary storage
Phase 1: คัดลอกส่วนแรกไป Tape 2 (แบบ reverse)
Phase 2: เดิน Tape 2 กลับต้นสมุด
Phase 3: เทียบ Tape 1 (ส่วนหลัง) กับ Tape 2 ทีละตัวอักษร
ถ้าเท่ากันทุกตัว → accept, ไม่เท่า → reject
เปรียบเทียบ: ทำด้วย 1-tape ยากมาก (ต้อง shift ไปมา) แต่ 2-tape ทำได้เร็ว!
จากห้องเรียน:
• Tape 0 = main tape (input/output)
• Tape 1, 2, ... = extra tapes = "ตัวแปรชั่วคราว" (temporary variables)
• เหมือนมี scratch paper ให้คำนวณ!
2-tape TM สำหรับ \(\{\omega c \omega \mid \omega \in \{a,b\}^*\}\):
Tape 0: input \(\omega c \omega\)
Tape 1: temporary storage

Phase 1: คัดลอกส่วนก่อน c จาก Tape 0 ไป Tape 1
Phase 2: เจอ c → เลื่อนข้าม
Phase 3: เปรียบเทียบส่วนหลัง c (Tape 0) กับ Tape 1 ทีละตัว
ถ้า match ทุกตัว + ทั้งสอง tape หมดพร้อมกัน → accept
Theorem: Multi-tape TM ไม่ทรงพลังกว่า standard (1-tape) TM
จำลอง k-tape TM ด้วย 1-tape TM ได้ (polynomial overhead)
วิธี: เก็บ k tracks บน tape เดียว คั่นด้วย # และใช้ marker สำหรับ head position

Undecidability & Halting Problem

ปัญหาที่ TM ตัดสินใจไม่ได้ (Undecidable)

ภาษา \(L\) เป็น undecidable iff ไม่มี TM ที่ decide \(L\) (ไม่มี TM ที่หยุดเสมอ + ให้คำตอบถูก)

Halting Problem

Halting Problem: กำหนด TM \(M\) และ input \(\omega\) → ตรวจว่า \(M\) จะหยุดบน \(\omega\) หรือไม่?

Theorem: Halting Problem เป็น undecidable — ไม่มีโปรแกรม (TM) ที่ตอบคำถามนี้ได้ทุกกรณี!
ทำไม Halting Problem แก้ไม่ได้?
สมมติมีโปรแกรม H ที่บอกได้ว่า "โปรแกรม M จะรันจบไหม?"
→ เราสร้างโปรแกรม D ที่ทำตรงข้ามกับคำตอบของ H!
→ พอเอา D ไปถาม D เอง → เกิด paradox (ถ้า H ตอบใช่ → D บอกไม่ / ถ้า H ตอบไม่ → D บอกใช่)
→ ดังนั้น H ต้องไม่มีจริง! ∎
💇 อุปมา: Barber's Paradox
ในหมู่บ้านหนึ่ง มีช่างตัดผม 1 คน — เขา "ตัดผมให้คนที่ไม่ตัดผมให้ตัวเอง" เท่านั้น
❓ แล้วใครตัดผมให้ช่างตัดผม?
• ถ้าเขาตัดให้ตัวเอง → เขาไม่ควรตัดให้ตัวเอง (ขัดแย้ง!)
• ถ้าเขาไม่ตัดให้ตัวเอง → เขาควรตัดให้ตัวเอง (ขัดแย้ง!)
→ ช่างตัดผมแบบนี้มีไม่ได้! (เหมือน Halting Problem)

🌀 อุปมา: "Liar's Paradox"
ประโยค: "ประโยคนี้เป็นเท็จ" — ถ้าเป็นจริง → เท็จ, ถ้าเท็จ → จริง — เกิด loop!

🎮 อุปมา: RPG NPC ที่แก้เกม
"สร้าง NPC ที่บอกได้ว่าเกมนี้ผู้เล่นจะแพ้ไหม" → ผู้เล่นสามารถทำตรงข้ามกับคำทำนาย → ทำนายไม่ได้!
เข้าใจผิด: Halting Problem แก้ไม่ได้ ≠ "โปรแกรมทั่วไปแก้ไม่ได้"!
บาง case แก้ได้ (เช่น loop ที่มี counter จำกัด) — แต่ไม่มี algorithm ที่แก้ได้ทุกกรณี
Proof sketch (Diagonalization):
สมมติมี TM \(H\) ที่ decide halting problem
→ \(H(M, \omega)\) = yes ถ้า M halt บน ω, no ถ้าไม่
สร้าง TM \(D\): เมื่อได้รับ input \(M\):
→ ถ้า \(H(M, M)\) = yes → \(D\) loop ตลอดกาล
→ ถ้า \(H(M, M)\) = no → \(D\) halt

ถามว่า: \(D(D)\) จะ halt หรือไม่?
• ถ้า \(D(D)\) halt → \(H(D,D)\) = yes → \(D\) loop ← ขัดแย้ง!
• ถ้า \(D(D)\) loop → \(H(D,D)\) = no → \(D\) halt ← ขัดแย้ง!
∴ TM \(H\) ไม่มีจริง ∎
สังเกต: Proof นี้ใช้ Diagonalization เหมือนกับที่พิสูจน์ \(2^{\mathbb{N}}\) uncountable!
→ เทคนิค Diagonalization ใช้ได้ทั้ง "เซต" (Ch.1) และ "ภาษา" (Ch.4)

Q11. พิสูจน์ว่า \(A - B\) เป็น uncountable ถ้า \(A\) uncountable และ \(B\) countable

สมมติ \(A - B\) เป็น countable

∴ \(A - B\) ต้องเป็น uncountable ∎
Q12. พิสูจน์ว่าเซตของ regular languages \(R\) เป็น countably infinite

Q13. พิสูจน์ว่า \(\{a^nb^n \mid n \geq 0\}\) ไม่เป็น regular
ใช้ Pumping Theorem:
สมมติ \(L\) เป็น regular → มี pumping length \(n\)
เลือก \(\omega = a^nb^n \in L\) (ความยาว \(2n \geq n\))
เขียน \(\omega = xyz\) ที่ \(|xy| \leq n\) → \(xy\) อยู่ในส่วน \(a^n\) → \(y = a^j, j \geq 1\)
Pump \(k=0\): \(xz = a^{n-j}b^n\) แต่ \(n-j \neq n\) → \(xz \notin L\) ← ขัดแย้ง!
∴ \(L\) ไม่เป็น regular ∎

Q30. \(\{a,b\}^* - \{a^nb^{2n} \mid n \in \mathbb{N}\}\) เป็น regular language หรือไม่?
ไม่เป็น regular!
สมมติ \(L = \{a,b\}^* - \{a^nb^{2n}\}\) เป็น regular

\(\overline{L} = \{a,b\}^* - L = \{a^nb^{2n}\}\) ก็ต้องเป็น regular
แต่ \(\{a^nb^{2n}\}\) ไม่เป็น regular (Pumping Theorem) ← ขัดแย้ง!
∴ \(L\) ไม่เป็น regular ∎
Q31. \(\{a^{p-2} \mid p \text{ is prime}\}\) เป็น regular language หรือไม่?
ไม่เป็น regular!
สมมติ \(L = \{a^{p-2}\}\) เป็น regular

\(L \cdot \{a^2\} = \{a^{p-2} \cdot a^2 \mid p \text{ prime}\} = \{a^p \mid p \text{ prime}\}\) ก็ต้องเป็น regular
แต่ \(\{a^p \mid p \text{ prime}\}\) ไม่เป็น regular ← ขัดแย้ง!
∴ \(L\) ไม่เป็น regular ∎

Q46. (Practice 2, Q6) จงพิสูจน์ A−B uncountable ถ้า A uncountable, B countable
Proof by contradiction:
สมมติ \(A - B\) countable
เนื่องจาก B countable: \((A-B) \cup B\) countable (countable ∪ countable = countable)
แต่ \(A \subseteq (A-B) \cup B\) → A countable ← ขัดแย้ง! (A uncountable)
∴ \(A - B\) uncountable ∎
Q47. (Practice 2, Q7) R = เซตของ regular languages ทั้งหมดบน Σ เป็น countably infinite
Proof:
\(R = \{L(\alpha) \mid \alpha \text{ เป็น regular expression}\}\)
เซตของ RE ทั้งหมด ⊆ \(\Sigma'^*\) โดย \(\Sigma' = \Sigma \cup \{\emptyset, \circ, *, \cup, (, )\}\)
\(\Sigma'^*\) เป็น countably infinite (เซตของสตริงทั้งหมดบน finite alphabet)
→ เซตของ RE ทั้งหมดเป็น countably infinite
→ \(R\) เป็น countably infinite ∎

มีภาษาที่ไม่ regular: \(\{a^p \mid p \text{ prime}\}\) ไม่ใช่ regular → \(\notin R\)
Q48. (Practice 3, Q6) ถ้า L ไม่เป็น regular แล้ว L เป็น infinite set
Proof (contrapositive):
พิสูจน์ contrapositive: ถ้า L finite → L regular
ถ้า \(L = \{\omega_1, \omega_2, \ldots, \omega_n\}\) เป็น finite
→ \(\omega_1 \cup \omega_2 \cup \cdots \cup \omega_n\) เป็น regular expression ที่ generate L
∴ L เป็น regular

ดังนั้น contrapositive: L ไม่ regular → L ไม่ finite → L เป็น infinite ∎
